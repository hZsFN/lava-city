# 外链游戏接入：开头接档，结尾交档

适用版本：交付包 v3.3.2，官方 SDK 1.0.0，通信协议 1，存档格式 SAVE_STATE v3。

游戏继续托管在自己的 HTTPS 网站，在大厅 iframe 中运行。SDK 是跨窗口消息桥：大厅把当前旅程的存档下发给游戏，游戏结束后提交真实结果，大厅后端验证保存并把处理后的存档交给下一关。无需上传外站源码，也无需改变游戏中间的玩法。

## 托管地址硬性要求（2026-11-08）

外链必须是**长期有效的公开生产地址**。以下情况一律不合格：

- 临时预览、开发预览、带登录/签名的地址。
- **IGA Pages（`*.preview.iga-pages.com`，或带 `iga_token` / `iga_time` 的链接）**。这类地址会先 `307` 设置 HttpOnly Cookie，再跳转；只在顶层新标签页能打开，进大厅 iframe 会返回 `401 未授权`。
- 只在新标签页打开成功、但在 sandboxed iframe 里 401/白屏的地址。
- 依赖第三方 Cookie、临时 token、登录态或很短有效期的地址。

**推荐**：Vercel / GitHub Pages / Cloudflare Pages / Netlify / 自己的 HTTPS 静态站，直接返回 200，不需要登录。  
**如果构建产物只能从预览站看到**：把构建产物导出为 ZIP 上传，或部署到上述公开站点后再提交外链。

自检：`node tools/check.mjs <URL>` 必须通过；再在真实大厅 iframe 里试玩，不能只在新标签页打开。

## 直接使用

在游戏入口中只引入一份 SDK，删除旧的内嵌协议副本，避免覆盖全局 WL：

```html
<script src="https://world.dayquay.com/sdk/v1/worldline.js"></script>
<script>
let save;
const acquired = new Set();

async function start() {
  try {
    save = await WL.ready();
    // 将 save.player、save.items、save.clues 用于你的角色、背包和开场画面。
    // 此处才启用“开始”按钮，不要提前用默认满血状态初始化实际玩法。
    startYourGame(save);
  } catch (error) {
    showError(error.message); // 页面内显示，并允许返回大厅/重新加载。
  }
}

async function win() {
  try {
    // save.player.hp 等应反映实际游玩结果；acquired 只记录本关实际收获。
    const receipt = await WL.complete(save, {acquiredItemIds: Array.from(acquired)});
    // 大厅将负责切换下一关。不要自行导航，不要在请求发出时就宣称保存成功。
    console.log(receipt.preview ? '试玩校验通过' : '大厅已保存');
  } catch (error) { showError(error.message); }
}

async function lose() {
  try {
    await WL.fail('探索失败', save, {acquiredItemIds: Array.from(acquired)});
  } catch (error) { showError(error.message); }
}
start();
</script>
```

`startYourGame`、`showError` 代表你自己的玩法和页面提示函数。可直接复制 `examples/03-external-sdk/` 作为可运行起点。固定版本地址为 `https://world.dayquay.com/sdk/v1.0.0/worldline.js`；`/sdk/v1/worldline.js` 保持协议 1 的兼容更新。不要同时引入远程 SDK 和旧 shared/save-protocol.js。

## 外链验收契约（v3.3.2，先看这一节）

| 类别 | 必须满足 | 怎么验 |
| --- | --- | --- |
| 托管 | 公开 HTTPS；无登录 Cookie/临时签名；重定向后仍 HTTPS | 直接打开 + 大厅 iframe |
| 嵌入 | 无 `X-Frame-Options: DENY/SAMEORIGIN`；CSP `frame-ancestors` 允许 `https://world.dayquay.com` | `node tools/check.mjs <URL>` |
| SDK | 入口引入 `https://world.dayquay.com/sdk/v1/worldline.js`；CSP `script-src` 允许该源 | 网络面板 + check.mjs |
| 接档 | 开局 `await WL.ready()`，用返回的 `save` 初始化；不要先跑默认满血 | mock-runner / 大厅非满血入场 |
| 交档 | 结尾 `await WL.complete(save,{acquiredItemIds})` 或 `await WL.fail(...)`；收到 `persisted:true` 才算保存 | mock-runner / 大厅成功+失败分支 |
| 资源 | 用 ES module/fetch/XHR/WASM 时，外站静态资源返回 `Access-Control-Allow-Origin: *` 或 `null`，`Cross-Origin-Resource-Policy: cross-origin` | check.mjs 抽查入口和首个 module + 浏览器 Network |
| 沙箱 | 不依赖 localStorage/IndexedDB/cookie/service worker、SharedArrayBuffer/线程、alert/confirm、弹窗/表单/下载；History API 可能受限 | 大厅真实 iframe |
| 数据 | 单独上传 `global-items.json`；只报实际取得的声明 ID；不传任意自定义 JSON | 大厅投稿 + 试玩 |
| 时长 | 4 分 30 秒内到达明确结局；300 秒看门狗只是兜底 | 作者实跑 + 大厅计时 |

**三层验收：**
1. `node tools/check.mjs <外链URL>`：自动检查 HTTPS、XFO、CSP、SDK 可达与首个 module 的 CORS。
2. `mock-runner.html` 填外链 URL：确认 `WL.ready()` 拿到非满血/旧道具存档，`WL.complete/WL.fail` 收到回执；出现“旧协议”警告说明没有走官方 SDK。
3. 真实大厅：主办方用非满血/旧道具入场，跑成功与失败两条分支，确认 `persisted:true`、下一关能读档，并填写 `完整流程自测记录.md`。

平台不扫描外站源码（外站可能需登录或有 CORS 限制），验收以实际行为为准。任一层失败，修复托管头或改用 ZIP 轨。

## API 与状态边界

| API | 行为 |
| --- | --- |
| `await WL.ready()` | 等待大厅下发当前旅程、本关的最新存档，成功后返回 save；15 秒无响应则报错，不把默认值冒充系统存档。可重复调用，不重复覆盖已开始的玩法。 |
| `await WL.complete(save, {acquiredItemIds: [...]})` | 提交成功结果；没有新道具传 []。只有收到大厅保存成功回执才 resolve；不合规则 reject。 |
| `await WL.fail(reason, save, {acquiredItemIds: [...]})` | 提交失败与真实收获，由平台生成遗物、墓碑和下一关状态。 |
| `WL.readSave()` | 同步读取 SDK 当前已接收的副本。首次入场仍应先 await ready；它不是每帧访问数据库的接口，也不会自动读取你引擎内部的血量。 |

作者负责把入场存档映射到自己玩法，并把游玩结果写回提交的 save。仅需开头和结尾接入，没有持续同步、每帧网络请求或强制修改内部架构。页面关闭前尚未提交的关内进度不会自动写入正式存档；刷新后恢复系统保存的本关入场状态。若项目自行处理大厅治疗/复活事件，可监听 `iw-admin` 并应用 `event.detail.save`；正式大厅的满血救援会恢复后重新载入本关。

本关只能上报自己已声明的道具 ID，不能伪造效果。上传时必须另选与当前作品配套的 `global-items.json`；没有跨关道具也要选空声明。旧背包、道具效果、出口结束语、关序与下一关由平台规则处理。

## 通信与验收

SDK 发送带版本的 IW_READY，大厅下发带本次 iframe 会话号的 IW_INIT_SAVE，SDK 收档后确认 IW_SAVE_ACK。结束请求包含会话号与请求编号，回执包含是否保存、存档、revision、step。大厅只接收当前 iframe 的消息，并绑定当前关；后端检查旅程、关序、revision 和已声明道具。重复完成请求不会再推进一关。

这是通信兼容性和交接正确性检查，不是对外站源码的认证或玩法反作弊证明。验收不扫描外站源码，也不凭同名函数判定通过；请实际用非满血、旧背包验证读档，再分别验证成功和失败交接。试玩回执明确为 preview=true、persisted=false；不会写正式旅程。正式回执 persisted=true 才表示已保存。

跨域和隔离 iframe 通过 postMessage 交换数据，无需放开 allow-same-origin，也无需把管理员口令或队伍 Token 放进游戏。SDK 只信父窗口，宿主只信当前 iframe；会话号用于区分本次连接，不证明游戏代码本身可信。浏览器不能允许大厅任意修改外站变量。

## 托管条件与故障处理

- 地址必须公开 HTTPS、长期有效，允许大厅 iframe 嵌入，重定向后的页面也须符合条件。不要使用登录预览页、依赖第三方 Cookie 或临时签名的地址；**禁止 IGA Pages 等临时预览链接（`*.preview.iga-pages.com`、`iga_token`/`iga_time`）**。
- CSP `frame-ancestors` 需允许大厅域名；X-Frame-Options: DENY/SAMEORIGIN 会拦截。若外站限制 script-src，也须允许 world.dayquay.com 的 SDK。
- **资源 CORS**：外链 iframe 是 opaque origin，ES module、fetch、XHR、WASM 流式加载都按跨域处理；静态托管必须返回 `Access-Control-Allow-Origin: *` 或 `null`，`Cross-Origin-Resource-Policy: cross-origin`。否则会出现“单独打开正常、进大厅白屏”。`node tools/check.mjs <URL>` 会抽查入口和首个 module。
- **沙箱存储**：不要依赖 localStorage/IndexedDB/cookie/service worker；刷新后从 `WL.ready()` 重新取存档。SDK 自己的存档会退回内存，但不会替你实现游戏内持久化。
- **线程与弹窗**：没有 SharedArrayBuffer/线程、alert/confirm、window.open、表单提交、下载；Unity/Godot 必须单线程。
- 401/403、页面禁止嵌入、SDK 下载失败发生在握手前；请换公开发布地址或上传 ZIP。仅单独打开外链成功不能证明大厅内可用。
- 不兼容的协议版本明确报错。交接失败保留当前旅程并展示原因；修正后可再次提交。交接回执超时表示结果未确认，不等于后端一定没保存，请返回大厅核对进度或刷新续玩，不要盲目重复奖励。
- SDK 不负责修复作者的私有托管授权、内部玩法变量或素材依赖。

## 作品 4 分 30 秒与五分钟看门狗

关卡应能在合理的最佳解法下于 **4 分 30 秒内完成完整流程并到达结局**，允许更短，不要求凑满 4 分 30 秒。后台可填写 1–270 秒的预计时长，默认 270 秒；预计时长用于编排参考，统一看门狗在本关开始后 300 秒触发遗物交接，不在 120/180/190 秒提前切走。刷新、重载和治疗不重置本关看门狗。仍保留入场前 5 秒安全区。

## 本地自测

解压完整交付包后运行本地 HTTP 服务，例如 `python -m http.server 8000`，访问 `http://localhost:8000/mock-runner.html`。选择示例目录内的 global-items.json，并填写示例 HTTP 地址；模拟器支持新版握手和明确标记的试玩回执。最终还须在真实大厅验证跨站托管和前后关交接。

外链托管头预检：`node tools/check.mjs https://你的地址/index.html`，先过 HTTPS/XFO/CSP/SDK/CORS，再用 mock-runner 跑握手。


## 时长与完整流程验收（v3.3.1，以本节为准）

作者必须用自己实际可执行的正常通关路线，至少完整跑过一遍作品：从点击开始，经过开场、核心玩法、必经对话/过场，直到出现明确的结局。该完整过程须在 **4 分 30 秒（270 秒）内**完成，允许更短，无须凑满 4 分 30 秒。不能只验证能启动，不能只给出理论最短路径，也不能把裁判强制跳关或看门狗超时当作自然通关。

提交前填写包内 `完整流程自测记录.md`，记录运行环境、实际入口、自己的操作路线、总用时和到达的结局。随后在大厅验证接档及成功/失败交档。该记录是作者自测，不等同于主办方已验收。

后台预计时长为 **1–270 秒，默认 270 秒**。它用于编排参考，不会提前截断更短或更长的实玩过程。平台看门狗保持 **5 分钟（300 秒）**，预留 30 秒缓冲用于加载及交接，超时才执行遗物交接。看门狗是兜底，不能代替作品自己的结局。刷新、重载、治疗不重置本关看门狗。
