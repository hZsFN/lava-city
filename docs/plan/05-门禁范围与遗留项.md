## 二、遗留项 #1：`src/boss/**` 是不完整交付（阻断级）

### 现状

`src/boss/` 在 master 上有 2 个文件：

```
src/boss/BossEntity.ts   1033 行，import three/webgpu
src/boss/preview.ts      313 行（仅远端有）
```

但它依赖 **5 个从未提交过的模块**：

```
./config      →  src/boss/config.ts      ❌ 不存在
./types       →  src/boss/types.ts       ❌ 不存在
./BossBrain   →  src/boss/BossBrain.ts   ❌ 不存在
./mathUtil    →  src/boss/mathUtil.ts    ❌ 不存在
./parts       →  src/boss/parts.ts       ❌ 不存在
```

### 后果

1. `npx tsc --noEmit` 报 6 个 `TS2307: Cannot find module`
2. 全量 gate 的 typecheck 阶段必失败 → 三路无法合并
3. `src/boss/**` **没有被 `src/main.ts` 或 `src/render/App.ts` 引用**，是未接线的死代码，但足以让整个构建崩

### 临时处置（已完成，2026-11-08 12:10）

| 措施 | 位置 | 说明 |
|---|---|---|
| typecheck 排除 `src/boss` | `tsconfig.json` 的 `exclude` | 让 master 恢复可构建 |
| 逻辑层 three 检查排除 `src/boss` | `scripts/check-contract.ps1` 的 `$excludedDirs` | 改为黄色警告，不阻断 |

**这两处都是临时措施，必须回滚。** 代码里已留注释标注回滚条件。

### 正式解法（Boss 那一路负责）

必须补齐这 5 个模块，并且把带 three 的部分拆到渲染层：

```
方案 A（推荐）：拆成两层
  src/boss/logic/**        纯逻辑，不 import three
    BossBrain.ts           行为树
    parts.ts               部位定义
    mathUtil.ts            向量工具（用 Vec3 元组，不用 THREE.Vector3）
    types.ts               类型
    config.ts              从 config/boss.json 读
  src/render/BossEntity.ts 几何与动画（可以 import three）
    ← 从 src/boss/BossEntity.ts 拆出来

方案 B（最省事）：整包搬走
  把 src/boss/** 全部移到 src/render/boss/**
  承认它是渲染层的一部分，不再要求纯 Node 可测

方案 C（最差）：放弃纯逻辑约束
  允许 src/boss import three
  → 代价：Boss 单测无法在 Node 跑，必须 jsdom + mock three
```

### 回滚临时措施的条件

当下面两条同时满足时，把 `src/boss` 从 exclude 名单移除：

1. `npx tsc --noEmit` 对 `src/boss` 零错误（5 个模块已补齐）
2. `src/boss/**` 里不再有 `from 'three'`

## 三、遗留项 #2：直接推 master 绕过合并流程

### 现象

```
c2372b8 | hZsFN | feat(boss): 重做伊格纳斯造型
```

这个提交**直接 push 到 master**，没走合并点，也没跑 gate。同类还有 `350f22e`、`ca57b71`。

### 后果

- master 一度 typecheck 全红
- 三路 rebase 后会继承这个红

### 建议

1. **加 pre-push hook**（本地防线）
2. **GitHub 上开 branch protection**（需要仓库 owner `hZsFN` 操作，`fireworkPx` 无权限）

hook 内容见 `docs/plan/06-pre-push-hook.md`。
