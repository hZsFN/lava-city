# 预授权段（复制粘贴用）

> 用法：把对应那一路的「预授权段」**放在第一条消息的最前面**，后面接该路的任务提示词。
> 作用：满足 `agent-work-protocol` skill §1「开工前必须拿到明确放行」的要求，之后不再逐条问你。
> 版本：v1.0 · 2026-11-08 11:52

---

## 为什么需要这一段

`agent-work-protocol` skill 第 1 节是硬规定：

> 接到任务后，Agent **只能**输出接单对齐模板，**不得开始任何实质操作**。
> 用户的**沉默、继续讨论细节、追问方案本身，都不算放行**。
> 只有用户明确说 **"开始"/"可以"/"授权"** 或点选等效确认，才能动手。

所以每个新对话第一轮，agent 读完 skill 后会停下来问"可以开始了吗"。
把预授权段放在第一条消息最前面 = 一次性满足这个要求，之后全程不停。

---

## 通用模板（改 `【作用域】` 那一处即可）

```
【预授权声明 · 本对话一次性生效，后续不再逐条申请】

主人已在本条消息中明确放行（等同"开始"），无需再输出接单对齐模板、
无需再确认开工许可，读完材料直接动手。

授权范围：
- 文件：读写【作用域】内的任何文件
- 命令：npm / npx / node / tsc / vitest / vite / powershell（仓库内脚本）
- git：add / commit / rebase / fetch / status / diff / log / stash
- 装依赖：npm install

仍然必须停下来问我（只有这五件）：
  ① git push
  ② 删除已有文件（git rm、rm、Remove-Item）
  ③ 修改 src/core/events.ts 或 src/core/config/*.json
  ④ 修改别人作用域的文件
  ⑤ 同一错误试了 3 次仍未通过

汇报节奏（覆盖 skill 默认的每 1–3 分钟心跳）：
- 不要发心跳。改为「完成一个文件」或「完成一个检查点」汇报一次
- 门禁报错自己修，不要报给我看
- 禁止问「可以开始了吗」，直接开始

判断原则：
- 拿不准某个决定 → 选「能跑通」的那个，在 handoff 里记一笔，继续
- 只有「改了会让别人编译不过」才停下来问

绝对不要执行（无论什么理由）：
  git reset --hard
  git clean -fdx
  git worktree remove
  git branch -D
  git push --force
  rm -rf / Remove-Item -Recurse -Force
需要撤销改动 → git checkout -- <单个文件>
```

## 消息结构（长这样）

```
第 1 段：预授权声明（上面那一段）
第 2 段：空行
第 3 段：任务提示词（"你负责《熔心孤塔》P2-B 的 B1 部分……"）
```

**顺序不能反**。预授权必须在最前面，因为 agent 读 skill 是第一条消息一开始就读的。

---

## 已经开着的对话怎么补

不用重开。发一条新消息：

```
【补发预授权 · 从现在起生效】

主人已明确放行，后续不再逐条申请。

授权范围：
- 文件：<你那一路的作用域>
- 命令：npm / npx / node / tsc / vitest / vite / powershell
- git：add / commit / rebase / fetch / status / diff / log / stash

仍然必须问我：① git push ② 删文件 ③ 改 src/core/** ④ 改别人作用域 ⑤ 同一错误 3 次

汇报：不发心跳，完成一个检查点说一次。禁止问"可以开始了吗"，直接继续。
绝对不要执行：git reset --hard / git clean -fdx / git worktree remove /
git branch -D / git push --force / rm -rf
```

然后接着说「继续做票 1」。

## 还有一层：新对话的审批策略

预授权段只解决「协议等待」。如果新对话本身是 `approval: ask`，工具层仍会弹窗。

新对话开局确认这两项（各会话独立，不继承）：
- 文件策略：`danger-full-access`
- 审批策略：`never`

这个会话已经是这个配置了，但**新开的三个对话各自独立**，要分别确认。
