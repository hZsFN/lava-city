# 02 · 血量接力规则（全队硬约束）

> 来源：主办方 2026-11-08 11:43 统一说明。
> **这条规则优先于 `熔心孤塔_设计与AI开发规划.md` 第 5.3 节。** 两者冲突处以本文为准。

## 一、主办方的原话（五条）

1. **不要预设初始血量。** 第一关的血量由主办方在后台配好、写进初始存档。之后每一关的血量，都是上一关结束时返回的那个值。禁止出现「开局 100 血」「三条命」这种写死的数，也禁止在自己这关收尾时把血回满。
2. **入口只做一件事：读。** 从存档里读 `player.hp`（当前血量）和 `player.max_hp`（血量上限）。**两个都要读** —— 上家可能加过上限，按固定格数画血条会画错。
3. **显示按比例来。** 血条 = `hp / max_hp`，实时画。玩家开局只剩 1 点血是完全正常的，别当成 bug 去"修复"。
4. **结束时把净变化交出去。** 把这关造成的加减算进去，返回最终的 `hp`，夹在 `[0, max_hp]` 之间。平台会交给下一个世界。
5. **血归零也有出口。** 不要白屏、不要卡死、不要偷偷回满。在关卡内处理掉：回到本关安全区重来，或者判定本关失败。血归零离场的玩家，平台按遗物规则处理 —— 名字挂上「前人的X」，并拿到一把兜底短刀继续往下走。

一句话：**血量是上一关交到你手上的接力棒，你只负责读它、改它、交出去。**

## 二、我们项目里必须改掉的三个地方

| 设计文档原文 | 冲突 | 改成 |
|---|---|---|
| §5.3「HP 100，脱战 4 s 后回复」 | 写死初始值 + 自动回满 | 删掉。hp/maxHp 全部从 `WL.readSave()` 读；不自动回复 |
| §3「玩家死亡 2 次（第 2 次直接失败）」 | 三条命写死 | 删掉。hp 归零直接 `WL.failLevel()`，没有"命"的概念 |
| §3 结算「死亡次数」 | 依赖复活机制 | 删掉。结算只统计：用时、击破次数、塔心剩余 |

## 三、本项目的具体实现（唯一版本，照这个写）

### 3.1 入口

```ts
const save = WL.readSave();
const maxHp = Math.max(1, Number(save.player.max_hp) || 1);
const hpAtEntry = Math.min(Math.max(0, Number(save.player.hp) || 0), maxHp);
// hpAtEntry 可能是 1，这是正常的，不许"修正"成 100
```

### 3.2 玩家受击

- Boss 直接命中玩家：**固定扣 1 点**（不按百分比）。因为入口血量可能是 1，按百分比扣会直接秒杀。
- 玩家受击后有 1.2 s 无敌帧（避免一次技能连扣多点）。
- 塔受到的伤害走塔自己的 `TowerHpChanged`，**不动玩家 hp**。
- 塔心的伤害走 `CoreHpChanged`，**不动玩家 hp**。塔心是关卡内的失败条件，不是玩家血量。

### 3.3 玩家 hp 归零

```ts
if (hp <= 0) {
  WL.failLevel("被熔渊之主击倒，倒在塔心前");
  return;
}
```

这是**唯一**的归零出口。不做复活、不做回安全区重来 —— 因为一旦允许复活，就得决定"复活后多少血"，而任何答案都等于自己定初始血量。判定失败最干净。

### 3.4 回血（唯一的加血途径）

击破成功（`ExecutionEnded`）时 **+1 hp**，`Math.min(maxHp, hp + 1)`。

这是"这关造成的加减"，合规。除此之外**没有任何回血来源**。

### 3.5 出口

三个出口分支，都要把 hp 夹紧后写回：

```ts
const finalHp = Math.min(Math.max(0, hp), maxHp);
save.player.hp = finalHp;
save.player.max_hp = maxHp;
// 通关
WL.completeLevel(CONFIG, save, { exitHook: "..." });
// 或认输
WL.failLevel("塔心被熔岩吞没", save, CONFIG);
```

`max_hp` 我们这关不改（没有加上限的机制），但**必须原样写回**，不能丢。

### 3.6 HUD

血条宽度 = `hp / maxHp * 100%`，实时更新。数字显示 `hp / maxHp`。**不画固定格数。**

## 四、验收（QA 必测）

1. 用 `seed-card.json` 起一局（hp 3 / max_hp 3），血条应为满。
2. 手动把存档改成 `hp: 1, max_hp: 3` 再进关，血条必须是 1/3，且游戏照常可玩。
3. 手动改成 `hp: 1, max_hp: 8`（上家加过上限），血条必须是 1/8，不能溢出、不能按 3 格画。
4. 被打一次扣 1，血条同步；击破一次回 1（不超过 max_hp）。
5. hp 归零时调到 `WL.failLevel`，不出现白屏、不卡死、不偷偷回满。
6. 通关后读 `save.player.hp`，必须等于界面上的最终值，且在 `[0, max_hp]` 内。
