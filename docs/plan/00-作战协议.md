## 0. 三十秒版

1. **一个仓库、四条分支、四个 worktree。** 每个会话在自己目录里写，只 commit 不 push。
2. **只有 S0（控制会话）能合并到 `master` 并 push。**
3. **只有 S0 能改 `src/core/events.ts` 和 `src/core/config/*.json`。** 你要新事件 → 写进 `handoff/你的会话.md` 的「契约申请」，不要自己加。
4. **逻辑层禁止 `import three`。** 塔、流程、玩家、战斗、Boss 只通过 `Bus` 事件 + `snapshot()` 通信。
5. **提交前必须 `npm run gate` 全绿。** 不绿不许 commit。
6. **每 30 分钟更新一次 `handoff/你的会话.md` 并 commit。** 这是四路互相知道对方在干什么的唯一途径。

## 3. Git 协作流程（每条命令都是完整可复制的）

### 3.1 开工（每个会话第一件事）

```powershell
# 进自己的 worktree（S1 为例）
cd E:\demo\wt-p2b

# 拉最新 master 并 rebase 到自己的分支
git fetch origin
git rebase origin/master

# 装依赖（第一次进这个 worktree 才需要）
npm install --no-fund --no-audit

# 确认自己的分支与身份
git status -sb          # 应显示 ## feat/towers-flow
git config user.name    # 应显示 fireworkPx
```

### 3.2 干活中的提交（只 commit，**不 push**）

```powershell
cd E:\demo\wt-p2b

# 1) 先跑门禁
npm run gate

# 2) 只 add 自己作用域内的文件（不要 git add -A）
git add src/towers src/flow tests/unit/towers tests/unit/flow handoff/S1-p2b.md

# 3) 提交（格式见 §3.5）
git commit -m "towers: 塔位注册与建拆（T-M2-01）"

# 4) 更新交接文件后立刻提交它
git add handoff/S1-p2b.md
git commit -m "handoff: S1 进度 11:30"
```

**S1/S2/S3/S4 一律不 push。** 你的提交留在本地分支，S0 合并时才推。

### 3.3 同步 master 的新契约（当 S0 广播"契约已更新"）

```powershell
cd E:\demo\wt-p2b
git fetch origin
git rebase origin/master
# 如果 rebase 冲突在你作用域外（src/core/**）→ 停下来找 S0，不要自己解
# 如果冲突在你作用域内 → 正常解，解完 npm run gate
```

### 3.4 S0 的合并流程（只有 S0 做）

```powershell
cd E:\demo\lava-city
git fetch origin

# 合并一条分支（--no-ff 保留分支痕迹，便于回滚）
git merge --no-ff feat/towers-flow -m "merge: S1 塔系统与流程（T-M2-01/03）"

# 合并后必须重新跑门禁（队友自证不算）
npm run gate

# 绿了才推
git push origin master
```

**合并冲突处理权**：冲突文件属于谁的写作用域，谁提供解冲突方案；S0 执行。两人不许互相改对方文件。

### 3.5 提交信息格式（便于回溯谁做了什么）

```
<模块>: <做了什么>（<票号>）
```

例：
- `towers: 塔位注册与建拆（T-M2-01）`
- `flow: 4:30 时间轴状态机（T-M2-03）`
- `player: 双形态武器骨架（T-M2-05）`
- `boss: 破绽控制器（T-M2-07）`
- `render: 熔岩海 TSL 材质（M1-01）`
- `handoff: S1 进度 11:30`

### 3.6 坏提交回滚（5 分钟内）

```powershell
# 只回滚自己的分支、还没被 S0 合并时
git reset --hard HEAD~1
```

若已被 S0 合并进 master 且 master 跑不起来：
```powershell
# S0 执行
git revert <坏提交sha> --no-edit
npm run gate
git push origin master
```


### 排障速查

| 现象 | 原因 | 修法 |
|---|---|---|
| `could not read Username` | extraheader 没继承 | `git config --get-all include.path` 应含 `E:/demo/.gitconfig` |
| `Duplicate header: "Authorization"` / HTTP 400 | extraheader 有两份 | `git config --local --unset-all "http.https://github.com/.extraheader"` |
| `schannel: AcquireCredentialsHandle failed` | openssl 没生效 | `git config http.sslBackend` 应为 `openssl` |
| `Failed to connect to github.com:443` | 代理没起 | `Test-NetConnection 127.0.0.1 -Port 12334 -InformationLevel Quiet` 应为 True |
| 中文文件名显示成 `\346\225...` | quotepath | `git config core.quotepath false` |

> 安全提醒：`E:\demo\.gitconfig` 里是 base64 明文 token（有效期至 2026-12-08）。**不要提交它、不要贴进对话、不要外传。**

## 5. 契约规则（最重要的一节）

### 5.1 什么是契约

`src/core/events.ts`（事件 + 快照）和 `src/core/config/*.json`（全部数值）。这是四路之间**唯一的耦合点**。

### 5.2 谁可以改

**只有 S0。** 其他任何会话修改 `events.ts` 都会被 `npm run contract` 拦下（哈希比对 `docs/plan/CONTRACT.lock`）。

### 5.3 我需要新事件怎么办

1. 在 `handoff/<你的会话>.md` 的「契约申请」一节写清楚：

```markdown
### 契约申请 #1（11:42 提出）
- 事件名：`TowerAmmoChanged`
- 字段：`{ towerId: string; ammo: number }`
- 触发时机：塔每次开火后
- 为什么已有事件不够：`TowerTargetHit` 不带剩余弹药，HUD 显示不了
- 提出人：S1
- 状态：待 S0 裁决
```

2. `git commit` 提交 handoff，然后**在对话里告诉 S0 一句话**（"契约申请 #1 已提"）。
3. S0 当天合并进 `master` 并广播 → 你 `git rebase origin/master` 就能用。

**不许先写代码再补申请。** 不许自己复制一份 events.ts。不许在别的文件里另起一套事件类型。

### 5.4 归属规则（避免两边重复发布同一事件）

| 事件 | 唯一发布方 | 说明 |
|---|---|---|
| `DebuffStackChanged` | **Boss** | 塔只发 `TowerTargetHit`，不许自己发 debuff 层数，否则双层叠加 |
| `BossSkillInterrupted` | **Boss** | 塔发 `TowerInterruptRequested`，Boss 掷骰成功后才发 |
| `MatchEnded` | **flow** | 一局只发一次；渲染/UI 只订阅 |
| `MatchPhaseChanged` | **flow** | 每个时间点切换时发 |
| `LavaLevelChanged` | **flow** | 熔岩高度变化时发 |
| `TowerHpChanged` | **towers** | `place()` 之后必须立刻发一次初始化 hp |
| `TowerSlotStateChanged` | **towers** | 塔位状态机变化时发 |

### 5.5 渲染层与 UI 的特殊约束

- 只允许 `bus.on(...)` 订阅和 `bus.snapshot()` 拉取。
- **禁止 `bus.emit(...)`**。要改状态必须通过逻辑层。
- 这样保证"谁拥有状态"永远清晰。

## 6. 逻辑层禁止 import three（第二红线）

**允许**：`import type { Bus } from '../core/events'`、`import towers from '../core/config/towers.json'`

**禁止**：`import * as THREE from 'three'`、`import { Vector3 } from 'three'`、任何 `three/*` 子路径

**为什么**：
1. 逻辑层单测要在纯 Node 下跑（`vitest.config.ts` 里 `environment: 'node'`），import three 会直接崩。
2. 渲染层要能整个换掉（WebGPU → WebGL2 回退）而不动玩法。
3. 你算位置用 `readonly [number, number, number]`（`Vec3` 类型）就够了，不需要 `THREE.Vector3`。

**需要向量运算时**：在 `src/core/math.ts` 里写纯函数（S0 负责），或者在自己模块里写局部函数。**不许引 three 就为了用 Vector3。**

`npm run contract` 会自动扫这五个目录，命中即失败。

## 11. 遇到问题怎么办

| 情况 | 做法 |
|---|---|
| 契约不够用 | 提契约申请，**不要自己加** |
| 需要改别人文件 | 写「跨目录请求」，**不要自己改** |
| 门禁报错看不懂 | 贴完整报错给 S0，不要猜着改 |
| 同一错误失败 3 次 | 停下，报告现象/已试/猜测/需要什么决定 |
| rebase 冲突在别人作用域 | 停下找 S0 |
| 发现自己要改的东西超出票范围 | 停下问 S0，不要自行扩大 |
| 时间不够做完整张票 | 先交付能跑的最小版本 + 在 handoff 写清缺什么 |
