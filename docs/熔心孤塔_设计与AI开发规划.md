## 1. 一句话定位与设计支柱

第一人称 **"塔防 × Boss 战"** 单局制动作游戏。玩家在被熔岩包围的高塔平台上布置防御塔牵制魔王，防御塔负责**压制、上 debuff、撬开 Boss 弱点**，玩家亲自补上最后一击造成爆发伤害。Boss 两阶段，弱点属性在两阶段间**物理 ↔ 法术**切换，迫使玩家中途重新布塔。

**单局 ≤ 4:30** 意味着这是一款"高密度、可反复挑战、看评分"的街机式 Boss 战，而不是慢节奏塔防。所有设计都服从于：

- **决策密度**：每 20～30 秒一次有意义的决策（布塔/换形态/击破/走位）。
- **零等待**：没有"等下一波"的空窗，Boss 从第 25 秒就在场。
- **可读性**：所有信息用颜色与形状编码，不依赖文字。
- **视觉冲击**：熔岩、辉光、体积光、击破慢镜是卖点，渲染管线为此服务。

核心乐趣三角：**布局决策 → 节奏阅读 → 亲手击破**。

## 2. 技术选型与渲染管线

### 2.1 关于 C++ 后端的判断：**不需要**

1. 单人、单局、无持久化对战，所有逻辑在客户端跑，没有权威服务器需求。
2. 浏览器瓶颈在 GPU 与主线程，不在"需要原生性能的计算"。一个 Boss + ≤ 8 座塔 + 几十个投射物，TS 完全够用。
3. 后端会引入网络延迟（第一人称对延迟敏感）、部署复杂度、离线不可玩，收益为零。
4. 若后期某子系统确需重计算（弹幕、流体），正确做法是 **Rust/C++ → WebAssembly 作为客户端模块**，而非后端。本方案预留扩展位，MVP 不做。
5. 可选轻量后端（排行榜/回放分享）：Node + Hono，与核心玩法解耦，M7 以后再议。

### 2.2 渲染管线选型：**Three.js WebGPURenderer + TSL，Forward+（分簇光照）为主，WebGL2 自动回退**

#### 候选对比

| 方案 | 画质上限 | 成熟度 | 对 AI Agent 友好度 | 结论 |
|---|---|---|---|---|
| Three.js **WebGPURenderer + TSL** | 高：计算着色器粒子、节点式后处理（Bloom/GTAO/SSR/TRAA/DoF/MotionBlur/LUT）、分簇光照 | 2025 起稳定，WebGL2 自动回退 | 高：TS 原生、文档与社区样例极多、TSL 以函数式节点写材质，比手写 GLSL/WGSL 更易被 Agent 生成与校验 | **选用** |
| Three.js WebGLRenderer + `postprocessing` 库 | 中高 | 非常成熟 | 高 | 作为回退路径保留 |
| Babylon.js（WebGPU） | 高，自带 Node Material Editor | 成熟 | 中：API 面更大、样例风格杂 | 备选 |
| PlayCanvas / Unity WebGPU 导出 | 高 | 商业引擎 | 低：Agent 难以在编辑器中操作，构建链不透明 | 不选 |
| 自研 WebGPU 渲染器 | 无上限 | — | 低，周期长 | 不选 |

#### 渲染架构决策

- **光照模型**：Forward+（Three.js `TiledLightsNode` 分簇光照）。理由：场景只有 1 个主光（熔岩反照/天光）+ 若干动态点光（塔的发光、Boss 核心、火雨落点、击破闪光，峰值约 30～60 盏），Forward+ 对透明物体、MSAA/TRAA 友好，比延迟渲染更适合有大量粒子与半透明熔岩的画面。
- **材质**：PBR（`MeshStandardNodeMaterial` / `MeshPhysicalNodeMaterial`），熔岩/岩甲/符文等特殊表面用 TSL 自定义节点材质（流动贴图、发光、三平面映射、顶点动画）。
- **阴影**：主光使用级联阴影（CSM，三级）；塔与 Boss 核心点光不投影（省预算），用 SSAO 补接触阴影。
- **全局光照**：预计算 HDR 环境（PMREM）+ 熔岩面作为面光源的近似（在 TSL 里用对熔岩平面的采样做下半球补光）+ GTAO。不做实时 GI。
- **后处理链（节点式 PostProcessing，按顺序）**：
  1. GTAO（环境光遮蔽，轻度）
  2. SSR（屏幕空间反射，仅黑曜石/湿岩材质开启 roughness 阈值）
  3. TRAA（时序抗锯齿，静态画面质量优先；运动剧烈时回落 SMAA）
  4. 体积光/雾（熔岩橙色雾 + 塔顶冷色光束，用屏幕空间光束/射线步进近似）
  5. Bloom（阈值高、半径大，熔岩与弱点高亮的核心效果）
  6. 运动模糊（仅在冲刺与击破慢镜时提高强度）
  7. 景深（仅击破镜头与开场/结算）
  8. 色差 + 暗角 + 胶片颗粒（轻量，强化"地心"氛围）
  9. 3D LUT 色彩分级（暖橙/冷青对比）
- **粒子**：TSL **计算着色器**驱动的 GPU 粒子（熔岩飞溅、火雨、岩屑、符文），单次 Instanced Draw，峰值 20 万粒子。
- **熔岩**：大平面 + TSL 节点材质：双层 flow map 流动、视差高度、发光裂纹、与平台边缘的菲涅尔溶解；上涨由 uniform 控制。
- **画质档位**：Ultra（全部开）/ High（关 SSR、体积光降采样）/ Medium（关 GTAO、Bloom 半分辨率、TRAA→FXAA）/ Low（WebGL2 回退，仅 Bloom+FXAA）。自动根据首 5 秒帧时间选档。
- **性能预算（1080p）**：16.6 ms/帧 @ 独显；Draw call < 400；三角 < 1.2 M；后处理总开销 < 5 ms；GPU 粒子 < 1.5 ms。
- **WebGPU 不可用时**：WebGPURenderer 自动回退 WebGL2 后端，TSL 材质自动编译为 GLSL；此时关闭计算粒子（改用 CPU 简化粒子）与 SSR。

### 2.3 技术栈总表

| 层 | 选型 |
|---|---|
| 语言 / 构建 | TypeScript（strict）/ Vite |
| 渲染 | Three.js（r17x+）WebGPURenderer + TSL + 节点式后处理 |
| 物理 | Rapier3D（WASM，`@dimforge/rapier3d-compat`）：角色控制器、分部位 hitbox、射线、投射物 |

## 3. 单局流程（4:30 时间轴）

```
0:00 ─ 0:20  醒来：黑屏旁白 → 睁眼（DoF 由模糊到清晰）→ 塔顶俯瞰熔岩湖；
             同时后台完成资源预热。熔岩口开始翻涌（Boss 预告）。
0:20 ─ 0:40  准备期（20 s）：玩家持 6 熔核，已有 1 座预置寒晶塔；
             塔位高亮，可快速放 2 座塔。倒计时醒目。
0:40 ─ 2:10  Boss 阶段 I「岩甲形态」（目标 90 s）：法术弱点。
             预期 3 次破绽窗口（约每 25～30 s 一次）。
2:10 ─ 2:25  转阶段过场（15 s，可操作）：Boss 跃入熔岩；熔岩上涨、2 座桥断裂、
             外环塔位解锁；玩家获得 1 次免费"全体重布"（战术视图自动打开，时间 0.1×）。
2:25 ─ 4:05  Boss 阶段 II「熔火形态」（目标 100 s）：物理弱点。预期 3 次破绽。
4:05 ─ 4:30  缓冲区（25 s）：若 Boss 未死，进入"熔岩吞没"狂暴——熔岩每秒上涨，
             4:30 整淹没塔心 = 失败。
4:30         硬上限。结算页（评分 S/A/B/C：用时、击破次数、塔心剩余、死亡次数）。
```

- **胜利**：阶段 II HP 归零。高手预期 3:30 左右通关。
- **失败**：塔心 HP 归零；玩家死亡 2 次（第 2 次死亡直接失败，死亡复活于塔顶耗时 3 s）；4:30 熔岩吞没。
- **节奏保证**：Director 系统保证任意 30 s 内至少出现一次破绽（见 7.3）。
- **设计取舍**：去掉原方案的小怪波次；"熔核经济"简化为 Boss 掉落 + 击破奖励；塔种类 MVP 收敛到 5 种，塔位 7+4 个；建塔瞬时（0.5 s 动画）。

## 4. 世界与场景设计

### 4.1 布局（俯视）

```
            熔岩 ~~~~~~~~~~~~~~~~~~~~~~~~~~~
        ~~~        [外环平台 E1..E4]          ~~~
      ~~~    ╔══════════════════════════╗     ~~~
     ~~~     ║   [中环平台 M1..M4]       ║      ~~~
     ~~~     ║      ┌────────────┐      ║      ~~~
     ~~~     ║      │  高  塔     │      ║      ~~~
     ~~~     ║      │ (2层+塔顶)  │      ║      ~~~
     ~~~     ║      └────────────┘      ║      ~~~
     ~~~     ║   [Boss 登场熔岩口]       ║      ~~~
      ~~~    ╚══════════════════════════╝     ~~~
        ~~~  熔岩 ~~~~~~~~~~~~~~~~~~~~~~~~ ~~~
```

- **高塔**：直径 14 m、高 24 m，2 层可走 + 塔顶。螺旋外廊与 1 条升降石台（3 s 直达塔顶，便于 4:30 节奏）。塔顶是狙击位；底层贴近**塔心（熔心核）**。
- **中环平台 M1–M4**：半径 20 m，4 个塔位。近 Boss，风险高。
- **外环平台 E1–E4**：半径 34 m，4 个塔位，阶段 II 解锁，经石桥连接（2 座会断）。
- **塔身塔位 T1–T3**：塔外壁第 2 层悬臂平台，3 个塔位。绝对安全但有仰角死区（Boss 贴塔基时打不到）。
- **总塔位 11 个**：阶段 I 开放 7（M×4 + T×3），阶段 II 再开 4（E×4）。
- **熔岩湖**：半径 55 m；落入 = 死亡。阶段 II 起上涨 1 m，4:05 后每秒上涨，E 位最先被淹（可在淹没前拆回收 70%）。

### 4.2 尺寸与手感基准

玩家眼高 1.7 m；移速 6.5 m/s，冲刺 11 m/s（含 0.25 s 无敌帧的闪避滑步）；跳高 1.2 m。Boss 阶段 I 高 9 m，阶段 II 高 11 m。塔基到中环边缘 6 m 走廊为主战区。

### 4.3 环境动态

熔岩上涨、桥断裂、火雨落点灼烧贴花、Boss 横扫留下的岩甲碎片（物理碎块，3 s 后沉入熔岩）。塔顶有常亮的冷色"地脉灯塔"光柱作为视觉锚点与方向参照。

## 5. 主角系统（第一人称）

### 5.1 操作

| 输入 | 行为 |
|---|---|
| WASD / Shift / Space | 移动 / 冲刺闪避 / 跳跃 |
| 鼠标 | 视角（Pointer Lock） |
| 左键 / 右键 | 主攻击 / 副攻击（蓄力或引导） |
| Q | 切换 **物理形态 ↔ 法术形态**（0.5 s） |
| E | 塔位交互：建/升/拆（径向菜单） |
| F | **击破**（仅在弱点"可击破"状态且距离达标时亮起） |
| Tab | 战术视图（时间 0.15×，俯视，远程搬塔，消耗战术点） |
| 1–5 | 快捷选塔 |
| R | 升降石台召唤（在塔内） |

### 5.2 双形态武器

**物理形态 — 熔岩重锤 / 岩锚**
- 左键：三段近战（30/30/60，范围 3 m，第三段击退）。
- 右键：蓄力 1.0 s 投掷岩锚，物理 80；命中弱点时**把自己拉到弱点处**（阶段 II 打背部与膝盖用）。

**法术形态 — 地脉法杖**
- 左键：连发火花（12/发，5 发/s），过热条 4 s / 冷却 2 s。
- 右键：引导 1.2 s "地脉穿刺"，法术 90，穿透岩甲打到阶段 I 的内嵌核心。

### 5.3 资源

- **HP** 100，脱战 4 s 后回复。
- **熔核**：开局 6；Boss 每掉 10% HP 掉 1 个（需到脚下捡）；每次击破 +2。塔造价 2～3，总共一局可建/升约 8～10 次。
- **战术点**：每次击破 +1，用于 Tab 远程搬塔。转阶段赠送 1 次免费全体重布。

### 5.4 击破（核心爽点）

弱点暴露 → 玩家用**匹配属性**攻击累积破绽值至 100 → 弱点"可击破" 3 s → 按 F：1.2 s 处决镜头（时间 0.2×、径向模糊、DoF、大数字），造成 Boss 阶段 HP **12%** 真实伤害 + 眩晕 3 s。错过则闭合。

## 6. 防御塔系统

### 6.1 原则

塔约占总伤害 **30%**，玩家普攻 **35%**，击破 **35%**。塔的核心职责是**控制、debuff、制造破绽**，不是主输出。每座塔有一条"对 Boss 特效"，这是布局策略的源头。

### 6.2 塔列表（MVP 5 种）

| 塔 | 属性 | 造价 | 射程 | 基础效果 | 对 Boss 特效 | 阶段适性 |
|---|---|---|---|---|---|---|
| **弩炮塔** | 物理 | 3 | 25 m | 单体 25 / 1.2 s | 命中 4 次叠 1 层**碎甲**：物理抗性 −8%/层，上限 5 | II 主力 |
| **符文聚能塔** | 法术 | 3 | 20 m | 单体 18 / 0.8 s | 叠**灼烙**：法术抗性 −8%/层，上限 5 | I 主力 |
| **寒晶塔** | 法术·控制 | 3 | 18 m | 范围减速 30% | 累积**冻结值**，满后 Boss 僵直 2.5 s 并**强制暴露弱点** | 两阶段主要破绽机 |
| **震地锚塔** | 物理·控制 | 3 | 12 m | 周期震击 | Boss 在范围内施法时 50% 概率**打断**，打断即暴露弱点 | 高风险高回报（必须放中环） |
| **嘲讽图腾** | 无 | 2 | 30 m | 无伤害，耐久 300 | 强制 Boss 攻击它 6 s（CD 20 s），用于拉位置、让 Boss 背对玩家 | 阶段 II 解锁背部弱点的关键 |

升级 1 次（造价 ×0.7）提升数值与上限；拆除返还 70%；建/拆 0.5 s。

### 6.3 塔位差异化

- 中环：震地锚 / 嘲讽最佳位；Boss 横扫会伤塔（耐久）。
- 外环：远程塔安全位；桥断、熔岩淹。
- 塔身：绝对安全，但只有射程 ≥ 20 m 的塔有效，且仰角死区。

## 7. Boss：熔渊之主「伊格纳斯」

### 7.1 阶段 I — 岩甲形态（HP 1400）

抗性：物理 70% / 法术 0%。弱点：胸口**地脉核心**（蓝色），平时被岩甲覆盖。**弱点属性：法术**。

| 技能 | 前摇 | 效果 | 破绽 |
|---|---|---|---|
| 岩拳横扫 | 0.9 s | 120° 扇形，伤 35，塔 −100 耐久 | 收手硬直 1.0 s（小破绽） |
| 跃击 | 1.6 s（玩家 > 14 m） | 砸向玩家，落地伤 50 | 落地岩甲张开 3 s → **核心暴露** |
| 地脉汲取 | 2.5 s 引导 | 回 5% HP，仅在塔心 8 m 内施放 | 被震地锚打断 / 冻结 → **核心暴露 5 s**（大破绽） |
| 岩柱升腾 | 1.2 s | 玩家脚下 3 处岩柱 | 无 |

AI 偏好：贴塔基砸塔心；仇恨：嘲讽 > 近身玩家 > 中环塔 > 塔心。

### 7.2 阶段 II — 熔火形态（HP 1400）

转阶段：岩甲崩裂，跃入熔岩再跃出，燃烧膨胀；熔岩上涨、2 桥断裂、外环开放。
抗性：法术 70% / 物理 0%。弱点：**背部冷却裂缝**（白金色，在背面）+ **双膝**（击碎后跪地 5 s）。**弱点属性：物理**。

| 技能 | 效果 | 破绽 |
|---|---|---|
| 熔岩吐息 | 正面 20 m 锥形持续 2.5 s | 施放中背对非目标 → **背部暴露**（嘲讽图腾的用武之地） |
| 熔岩冲撞 | 冲向目标，撞塔即毁 | 撞墙 / 撞震地锚 → 眩晕 3 s，**膝盖暴露** |
| 火雨 | 全场 10 处落点，塔也受伤 | 无 |
| 自燃爆发 | 周身 10 m 爆炸，**清除自身所有 debuff** | 冻结值满可阻止 |

### 7.3 AI 架构

- **效用行为树**：每 0.5 s 评估，技能得分 = 冷却可用 × 距离条件 × 情境效用（塔心附近→汲取高分；玩家远→跃击高分）。
- **破绽控制器**：独立模块，监听 `SkillInterrupted / SkillRecovery / FreezeFull / KneeBroken`，发布 `WeaknessExposed{part, element, duration}`。
- **导演（Director）**：节奏兜底——30 s 无破绽则下一技能强制选"带破绽收招"的技能；连续两次击破后倾向自燃爆发 / 火雨（惩罚贪心）；4:05 后进入狂暴（技能冷却 ×0.6）。
- **可播种随机**：所有随机使用 seed，便于回放与 Agent 复现。

## 8. 伤害、破绽与数值模型

```
最终伤害 = 基础
         × (1 − 抗性 + Σdebuff减抗)            // 抗性下限 −30%（最高 1.3×）
         × 弱点倍率（命中弱点且属性匹配 2.5 / 命中弱点属性不匹配 1.2 / 其他 1.0）
击破     = 阶段最大 HP × 12%，真实伤害，无视以上
```

破绽值累积：匹配属性 +1/伤害点；不匹配 +0.25；塔来源 ×0.5。

每阶段目标：3 次击破（36%）+ 塔 30% + 普攻 34%，共 90～100 s。这些比例是**平衡 Agent 的自动化验收目标**（见 15.3）。

## 9. 策略空间自检

- **阶段 I 标准解**：中环 1 寒晶 + 1 震地锚（卡地脉汲取），塔身 2 符文，1 嘲讽拉离塔心；法杖右键打核心。
- **转阶段**：免费重布——拆符文换弩炮放外环；嘲讽挪到能让吐息背对玩家的位置。
- **贪心惩罚**：全输出无控制 → 自燃爆发清层，时间不够。
- **高手解**：震地锚卡冲撞路线制造撞晕 + 岩锚拉近膝盖 → 连续击破，3:20 通关。

设计验证指标：不建嘲讽的阶段 II 平均用时应明显长于建嘲讽（≥ 25%）。

## 10. UI / UX

- **HUD**：左下 HP / 形态图标 / 过热条；右下 熔核、战术点；顶部 Boss 双段血条 + 抗性图标 + debuff 层数；顶中 **倒计时（4:30）**。
- **准星**：命中弱点变色；破绽值环形进度。
- **弱点指示**：屏幕边缘脉冲 + 世界空间箭头；颜色 = 属性（蓝=法术，白金=物理）与形态图标一致。
- **Telegraph**：所有 ≥ 0.9 s 前摇的技能有地面贴花 + 专属音效。
- **建塔径向菜单**：造价、射程预览圈、一句话特效。
- **教学**：首遇事件 3 s 提示；只在第一局出现。
- **结算**：S/A/B/C 评分、伤害构成环图、"再来一局"（≤ 2 s 重开）。

## 11. 美术方向与资产生产管线

### 11.1 方向

暗红/橙黑熔岩 × 冷色黑曜石高塔，冷暖对比。Boss 阶段 I 深灰岩甲 + 蓝核心；阶段 II 橙红燃烧 + 白金裂缝。弱点色 = 属性色，不用文字。镜头：开场 DoF 渐清、击破径向模糊 + 慢镜、转阶段熔岩喷发 Bloom 爆点。

### 11.2 面向 AI Agent 的资产生产管线（无人力美术）

| 资产 | 生产方式 | 验收 |
|---|---|---|
| 场景硬表面（塔、平台、桥） | Blender bpy 脚本程序化建模（参数化，可重跑）+ 程序化 PBR 材质（TSL 节点）| 三角数、UV、碰撞体自动检查脚本 |
| Boss / 小道具 | 生成式 3D（文本→网格）生成底模 → bpy 重拓扑/减面/自动 UV → 导出 GLB；Boss 分部位命名约定 `WP_Core / WP_Back / WP_KneeL / WP_KneeR` | 骨骼命名、部位空节点存在性测试 |
| 动画 | Mixamo 人形动画重定向（bpy 脚本），Boss 非人形部分用程序化（TSL 顶点动画、Rapier 骨骼驱动） | 动画时长 = 技能前摇/生效/收招配置 |
| 纹理 | 生成式纹理 + 程序化噪声；统一转 KTX2 | 分辨率、压缩格式检查 |
| 熔岩 / 粒子 / 符文 | 纯 TSL 程序化 | 截图回归 |
| 音效 | 生成式音效 + 程序化合成（Web Audio）；统一 LUFS 响度归一 | 时长、响度脚本 |
| HDR 环境 | 程序化天空盒（地心洞穴，Blender 烘焙） | PMREM 预处理 |

所有资产生成脚本入库（`tools/art/*.py`），**资产 = 代码**，Agent 可重跑、可 diff。

## 13. AI Agent 开发流程规划

> 核心思想：**先契约、后并行；每个任务可验证；资产即代码；遥测驱动平衡。**

### 13.1 Agent 角色

| 角色 | 职责 | 读写范围 |
|---|---|---|
| **架构/编排 Agent**（1） | 维护本文档与 `AGENTS.md`，定义 `events.ts` / `config/*.json` 契约与类型，拆任务、派发、合并评审 | 全库（主要是契约与 CI） |
| **渲染 Agent**（1） | `render/`：WebGPU 管线、TSL 材质、后处理、粒子、画质档位、性能预算 | `src/render/` |
| **玩法 Agent ×2** | A：`player/` + `combat/`；B：`towers/` + `flow/` | 各自目录 |
| **Boss Agent**（1） | `boss/` 全部，含技能、破绽、Director | `src/boss/` |
| **美术管线 Agent**（1） | `tools/art/`、资产生成与导出、命名约定检查 | `tools/art/`, `public/assets/` |
| **UI/音频 Agent**（1） | `ui/`, `audio/` | 各自目录 |
| **QA Agent**（1） | 写/跑 Vitest、Playwright、截图回归、性能脚本；复现 bug 产出最小回放 | `tests/`, `tools/perf/` |
| **平衡 Agent**（1） | 机器人自动对局、遥测分析、调 `config/*.json` 直到命中第 8 节目标 | `src/core/config/`, `tools/balance/` |

并行原则：**同一时间同一目录只有一个 Agent 写**；跨目录需求通过修改契约 → 架构 Agent 评审 → 广播。

### 13.2 仓库约定（写入 `AGENTS.md`）

- 命令：`npm run dev | build | typecheck | lint | test | test:e2e | perf | balance`。
- 提交前必须通过：`typecheck + lint + test`；涉及 `render/` 必须跑 `perf`（帧时间预算）与截图回归。
- 所有数值改动只在 `src/core/config/`；所有新事件必须先加到 `events.ts` 并写注释。
- 每个任务 PR 描述包含：目标、验收命令、截图/回放文件路径。
- 禁止：在逻辑层 import three；硬编码数值；无种子的随机。

### 13.3 任务生命周期（每张票）

```
Spec（架构 Agent 写，含验收标准与测试命令）
  → Contract（若需新事件/配置字段，先合并契约 PR）
  → Implement（功能 Agent，在隔离分支）
  → Self-verify（typecheck/lint/test/perf/截图）
  → QA Agent 独立复核（跑回放、补测试）
  → 架构 Agent 评审合并
  → 遥测/平衡 Agent 下一轮数据
```

票的粒度：**单个 Agent 2～6 小时可完成且可独立验证**。例如"实现寒晶塔冻结值累积并在满值时发布 `FreezeFull` 事件，单测覆盖累积/衰减/上限"。

### 13.4 Agent 的"眼睛"：可视化验证能力

Agent 不能像人一样玩游戏，必须给它们可编程的观测手段：

- **无头截图**：Playwright + Chromium（WebGPU 需 `--enable-unsafe-webgpu --enable-features=Vulkan`；CI 无 GPU 时用 WebGL2 回退跑截图基线，渲染 Agent 在带 GPU 的机器上跑 WebGPU 基线）。固定种子 + 固定相机位 → 像素级 diff 阈值。
- **场景快照 API**：`window.__game.snapshot()` 返回 Boss 状态、塔列表、玩家位置、时间轴，用 JSON 断言代替"看屏幕"。
- **脚本化玩家**：`tools/balance/bot.ts` 实现策略机器人（标准解 / 贪心解 / 高手解），可在 Node 无头模式下以 100× 速度跑完整一局，产出遥测。
- **回放**：输入 + 种子 → 确定性重放，bug 票附回放文件。
- **帧时间预算**：`npm run perf` 在固定场景（阶段 II 火雨峰值）采样 10 s，超预算即失败。

### 13.5 迭代节奏

- **日循环**：早——架构 Agent 派票；中——功能 Agent 并行；晚——QA 跑全量，平衡 Agent 跑 200 局机器人对局出报告。
- **周循环**：合并到可玩版本，产出一段 30 s 自动录制视频（Playwright 录屏）供人类评审"画面是否精美"——这是唯一需要人类主观判断的环节。
- **人类介入点**：画面审美、手感微调、最终平衡定稿。其余全部自动化。

## 16. 风险与应对

| 风险 | 应对 |
|---|---|
| 4:30 内塞不下两阶段+转阶段，节奏赶 | 时间轴参数全外置；Director 兜底；若机器人数据显示超时率 > 20%，优先削 Boss HP 而非技能 |
| Boss AI 手感差（最大风险） | M3 最早做；破绽间隔遥测硬断言；可播种回放 |
| WebGPU 兼容性 | WebGL2 自动回退 + Low 档；首屏能力检测 |
| 后处理吃满预算 | 每项后处理单独预算与开关；TRAA 替代 MSAA；半分辨率 Bloom |
| Agent 无法判断"精美" | 周循环人类评审录屏；渲染 Agent 以参考图像的色彩直方图/对比度指标做粗校验 |
| 生成式 3D 资产质量不稳定 | 多候选生成 + 自动检查筛选；关键视觉（熔岩、弱点）全部 TSL 程序化，不依赖生成模型 |
| 多 Agent 冲突 | 目录所有权 + 契约先行 + 架构 Agent 单点合并 |

## 17. 立即执行的第一步（架构 Agent 的第一张票）

1. `npm create vite@latest -- --template vanilla-ts`；安装 `three @dimforge/rapier3d-compat lil-gui stats-gl`，dev 依赖 `vitest @playwright/test eslint typescript`。
2. 建第 12.1 节目录；写 `events.ts` 契约 v1（`WeaknessExposed / WeaknessBroken / TowerBuilt / TowerDestroyed / BossSkillStart / BossSkillInterrupted / BossPhaseChanged / MatchPhaseChanged / PlayerDied / LavaRise`）与 `config/*.json` 骨架。
3. `main.ts`：WebGPURenderer（含回退检测）+ 固定步长循环 + Pointer Lock 相机 + Rapier 世界。
4. 灰盒：CylinderGeometry 塔、RingGeometry 平台、PlaneGeometry 熔岩（先用纯色发光 + Bloom），11 个塔位 Object3D 登记进 `config/arena.json`。
5. `debug/` 面板、`window.__game.snapshot()`、输入录制。
6. `AGENTS.md`（第 13.2 节）、CI（typecheck/lint/test/e2e 冒烟/截图基线）。
7. 派发 M1（玩法 A）、M2（玩法 B）、M3（Boss）、M5（渲染）、M6（美术）五张并行票。
