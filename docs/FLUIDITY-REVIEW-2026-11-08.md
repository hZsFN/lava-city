# Demo 流畅度优化交付

基线：`204945a`（2026-11-08 拉取的 origin/master）。分支：`perf/demo-fluidity-20261108`。
范围：10 分钟内的热点优化；原工作区未提交的塔外观等改动未纳入本 PR。

## 变更与依据

- 塔位每次同步改读已有事件快照，不再为每个塔位构造 SlotView；颜色对象就地更新，复用存活塔集合，遍历 Map 时不再复制 key 数组。11 个塔位原先每次普通同步创建 22 个 Color，俯视额外创建 11 个；现在这些 Color 分配为零。此为代码路径计数，不是帧率实测。
- 保留启动时的 P90 自动选档，增加战斗期间持续负载检测：5 秒冷却后，在至少 3 秒且至少 3 帧的窗口中，75% 以上帧超过原配置阈值才降低一档。只降不升，避免反复重建渲染管线；手动档位及 URL 指定档位优先，raw 和后处理计时模式不参与自动降档。
- 后台帧不推进逻辑或提交渲染；可见性变化时重置帧时间、FPS 统计和负载窗口，避免恢复时补入后台长间隔。
- 隐藏的后处理面板不再定期写 DOM；调试 HP/FPS/消息仅在文本变化时更新。
- 每帧更新的余烬实例矩阵标记为动态上传用途。

## 未验证与后续复核

没有完成真实 GPU 的优化前后 FPS / P95 对照、全关卡实机试玩或音频压力测试，不声明帧率提升百分比。代码与单元测试验证不能替代实际画面验收。
复核建议：同一设备分别运行基线与 PR，跳过开场、建满塔、进入 Boss 两阶段并持续转动镜头；记录稳定窗口帧时间、卡顿次数及画质档位。按 H 手动选档应锁定；切到后台再返回应无逻辑补跑。
高刷屏镜头仍随现有 60 Hz 逻辑调用同步，这项需进一步解耦演出镜头与固定步长，并做专项交互回归。

回滚：PR 未合并前关闭即可；合并后可 revert 本 PR。交付包随源代码一并版本化。
