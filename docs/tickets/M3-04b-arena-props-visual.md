# 票 M3-04b · 场地道具细节规格（渲染 / 特效 / 音频 / 可读性）

> 状态：**设计稿（未落库）** · 2026-11-08 14:35
> 父票：`docs/tickets/M3-04-arena-props.md`（布局与数值，已交付）
> 本票只回答一件事：**这 29 件道具具体长什么样、怎么碎、怎么发声、玩家怎么一眼认出来。**
> **只新增文件，不改任何已有文件。**

---

## 【0. 为什么还要一张细节票】

M3-04 给的是"东西摆在哪、挡什么、多高多重"。但把它交给渲染 Agent 会立刻卡住，因为父票没说：

- 3.6×0.8×2.2 的壁垒**具体是什么形状**？一块方砖，还是三块错位堆叠的岩板？
- 240 HP 打掉时**怎么碎**？整块消失，还是掉 8 块碎片？
- 玩家站在掩体后面，**怎么知道挡住了**？没有任何反馈就是"玄学判定"。
- 四种道具同场，**怎么在纯黑环境里一眼分辨**？M1-03 的结论是"石头只能靠光照显现"，那这些道具就必须靠**轮廓 + 底部反光 + 符文**三种手段区分。

本票逐条给出可执行的规格。**每条都标注了"依据"或"取值理由"**，没有依据的写"需实测"。

---

## 【1. 统一视觉语法（最重要的一节）】

M1-03 的硬结论：**光只从下面来，向上的面照度为零**。玩家第一人称 90% 时间在平视/俯视，看到的主要是"向上的面"。

所以道具的可读性**不能靠表面明度**，只能靠三件事：

| 手段 | 作用 | 具体做法 |
|---|---|---|
| **① 轮廓剪影** | 远距离识别"这里有个东西" | 每种道具的**顶部形状**必须不同（见下表） |
| **② 底部反光边** | 让石头从黑背景里"浮起来" | 底面往下 0.08 m 处加一圈 `TorusGeometry` 或倒角斜面，接住熔岩底光 |
| **③ 符文标记** | 近距离识别"这是什么类型" | 遮挡物=橙符文、防御物=冷青符文、平台=无符文（靠高度读） |

**顶部形状区分表**（这是本票的核心识别设计）：

| 道具 | 顶部轮廓 | 剪影特征 | 一眼认出 |
|---|---|---|---|
| 熔渣壁垒 | 三块错位岩板，最高一块偏左 | **锯齿状、不平整** | "一堵塌了一半的墙" |
| 黑曜石棱柱 | 六棱柱，顶端斜切 15° | **细高、尖、有反光棱线** | "一根柱子" |
| 塌陷矮墙 | 两块矮石，中间断开 0.3 m 缺口 | **低、断、有缺口** | "可以翻过去的矮墙" |
| 塔心护壁 | 弧形墙，顶部内倾 | **弧形、包住塔心** | "一圈护栏" |
| 寒铁镇石 | 矮圆台 + 中央一根细铁针 | **扁平、有针、地面有光环** | "站上去的地方" |
| 跳跃平台 | 正八边形平板，边缘倒角 | **规整、几何、平** | "能站上去的台子" |

**关键取舍**：平台**不用符文**。因为平台是"中性的地形"，用符文会让玩家误以为它有魔法效果。它只靠**规整的八边形轮廓**和**边缘倒角接光**来识别——这正好与"错位岩板"的壁垒形成强对比。

## 【2. 逐件几何规格（程序化，不用外部模型）】

全部用 `*Geometry` 拼装，遵守 `Spire.ts` 的做法：**先建几何 → 合并进三个静态批次 → 一个 draw call**。

### 2.1 熔渣壁垒 `slagBulwark`（4 件）

```
尺寸：宽 3.6 × 厚 0.8 × 高 2.2
构造：3 块岩板错位堆叠
  ├─ 底块  BoxGeometry(3.6, 0.9, 0.8)   center (0, 0.45, 0)
  ├─ 中块  BoxGeometry(2.8, 0.8, 0.75)  center (-0.3, 1.25, 0.02)   // 偏左 0.3，制造错位
  └─ 顶块  BoxGeometry(1.9, 0.5, 0.7)   center (-0.6, 1.85, -0.02)
底部反光：BoxGeometry(3.7, 0.1, 0.85) 于 y=0.02，用 obsidian 材质（metalness 0.5 接底光）
符文：正面一条 BoxGeometry(2.2, 0.04, 0.02) 于 y=1.25, z=+0.4，用 rune 材质
三角数：3×12 + 12 + 12 = 60
```

**为什么错位**：一块完整的方砖看起来像"人造障碍物"，三块错位堆叠看起来像"熔岩爆裂后凝固的岩渣"——符合"熔渣"这个名字，也符合 `docs/concept/README.md` 的"低多边形岩块感、大块面、硬边"。

### 2.2 黑曜石棱柱 `obsidianPillar`（4 件）

```
尺寸：半径 0.6 × 高 4.6
构造：
  ├─ 柱体   CylinderGeometry(0.6, 0.72, 4.6, 6)   // 6 段 = 六棱柱，符合"棱柱"
  ├─ 顶盖   CylinderGeometry(0.55, 0.6, 0.25, 6) 于 y=4.6，再 rotateZ(15°) 斜切
  └─ 底裙   CylinderGeometry(0.9, 1.0, 0.3, 6)   于 y=0.15
材质：obsidian（metalness 0.5, roughness 0.22）
底部反光：底裙已自带（金属度高，反射熔岩）
三角数：6 段柱体 ≈ 24 + 顶盖 24 + 底裙 24 = 72
```

**为什么用黑曜石材质**：`docs/concept/README.md` 005 图明确"棱线是全图唯一的镜面高光"。4 根棱柱在场上是**唯一的高反光物体**，玩家靠"哪里有镜面反光"就能定位撞点——这比加任何 UI 标记都自然。

**顶端斜切 15° 的理由**：垂直切断的圆柱看起来像管道。斜切后轮廓是斜的，与"被熔岩烧蚀过"的叙事一致，且**在纯黑环境里斜切面能接到一点底光**，让顶部不至于完全消失。

### 2.3 塌陷矮墙 `brokenParapet`（4 件）

```
尺寸：宽 2.4 × 厚 0.6 × 高 1.1
构造：两块矮石 + 中间 0.3 m 缺口
  ├─ 左块 BoxGeometry(1.0, 1.1, 0.6)  center (-0.7, 0.55, 0)
  ├─ 右块 BoxGeometry(1.0, 0.9, 0.6)  center (+0.7, 0.45, 0)   // 右块更矮，塌陷感
  └─ 缺口处：无几何（玩家可以看穿）
底部反光：BoxGeometry(2.5, 0.1, 0.65) 于 y=0.02
符文：无（低掩体不给符文，避免与壁垒混淆）
三角数：12 + 12 + 12 = 36
```

**缺口是功能性的，不是装饰**：缺口宽 0.3 m < 玩家半径 0.35×2=0.7 m，所以**玩家钻不过去**，但**视线和吐息能从缺口穿过去**。这让矮墙有一个反直觉的特性：站在缺口正后方**反而挡不住吐息**。这是刻意的——玩家必须学会"躲在石块后面，不是躲在墙后面"。

**这条要不要保留？** 我倾向保留，因为它让"低掩体"有真实的空间逻辑。但如果实测发现玩家频繁踩坑，可以改成实心（缺口只在视觉上，判定按整面墙算）。**标注为待实测项。**

### 2.4 塔心护壁 `coreWard`（3 件）

```
尺寸：弧长 5.0 × 厚 0.5 × 高 2.4（弧形，半径 9.6）
构造：8 段 BoxGeometry 沿弧线排布，每段宽 5.0/8=0.625，段间错位 ±0.05
  for i in 0..7:
    angle = -arcHalf + (i+0.5)*(arc/8)
    BoxGeometry(0.625, 2.4, 0.5) 于 (cos(angle)*9.6, 1.2, sin(angle)*9.6)
顶部内倾：每段顶加 BoxGeometry(0.625, 0.3, 0.55) 向内倾斜 10°
底部反光：每段下方 BoxGeometry(0.64, 0.1, 0.55) 于 y=0.02
符文：每段正面一条竖直 BoxGeometry(0.04, 1.6, 0.02)，冷青色
三角数：8 段 × 4 部件 × 12 = 384
```

**为什么分成 8 段而不是一个弧形几何**：碎片化后**破坏动画可以逐段崩塌**（见 §4），比整块消失有说服力。8 段是"看起来是弧形"和"碎片数量可控"的平衡点。

**冷青符文是唯一例外**：父票原则说"遮挡物橙符文、防御物冷青符文"。但 `docs/concept/README.md` 003 图说"冷青光是全场最强视觉锚点，只属于地脉灯塔"。护壁用冷青会不会抢灯塔的视觉地位？

**判断：不会，但要压暗。** 灯塔是**向上打的光柱**（高 60 m），护壁是**地面上的矮墙**。两者形态完全不同。但护壁的冷青 `emissiveIntensity` 应设为 **0.9**，而灯塔是 2.2+——差 2.4 倍，不会混淆。

### 2.5 寒铁镇石 `frostAnchor`（2 件）

```
尺寸：半径 0.8 × 高 0.5
构造：
  ├─ 圆台   CylinderGeometry(0.8, 0.9, 0.35, 12)  于 y=0.175
  ├─ 台面   CylinderGeometry(0.7, 0.7, 0.06, 12)  于 y=0.38
  ├─ 铁针   CylinderGeometry(0.04, 0.06, 0.5, 6)  于 y=0.66   // 细针，顶端 0.04
  └─ 光环   RingGeometry(2.85, 3.0, 48) 于 y=0.02，平铺
材质：圆台/台面 = rock，铁针 = obsidian，光环 = 冷青 rune
三角数：圆台 48 + 台面 48 + 铁针 24 + 光环 96 = 216
```

**铁针的作用**：0.5 m 的矮台在纯黑里几乎看不见（向上的面全黑）。加一根 0.5 m 的细铁针，**剪影立刻变成一个"有尖的东西"**。而且铁针是 obsidian（高反光），能接住底光，成为一个小亮点。

**光环是判定可视化，不是装饰**：3 m 半径正好是父票的 `aura.radiusM = 3.0`。玩家看到光环边缘，就知道"站进去有减伤"。**这条光环必须与实际判定半径完全一致**，否则就是骗玩家。建议在实现时从同一个 config 字段读，不要各写一个数。

### 2.6 跳跃平台 `jumpLedge` / `jumpHigh` / `bridgePier`（12 件）

```
尺寸：1.8 × 1.8 正八边形（不是正方形！）
构造：
  ├─ 台面   CylinderGeometry(0.95, 0.95, 0.18, 8)  于 y = h - 0.09
  ├─ 侧壁   CylinderGeometry(0.95, 0.82, h - 0.18, 8) 于 y = (h-0.18)/2
  ├─ 描边   RingGeometry(0.85, 0.95, 8) 于 y = h + 0.005（极细发光边）
  └─ 底裙   无（悬空台子，底部朝下会被底光照亮，自然可见）
材质：台面/侧壁 = rock，描边 = rune（emissiveIntensity 0.5）
三角数：32（台面）+ 32（侧壁）+ 16（描边环）= 80 每件 × 12 = 960
```

**为什么是正八边形不是正方形**：`Spire.ts` 的塔身是八棱柱（`sides: 8`），中环塔位底座也是八边形（`CylinderGeometry(size, size, 0.72, 8)`）。**八边形是本项目的几何母题**。平台用八边形，与场地语言统一；用正方形会像"临时加的方块"。

**三种高度用同一几何、只改参数**：这样渲染侧只有一份代码，12 件平台共享同一个 `BufferGeometry` 生成函数。高度不同自然形成"阶梯感"。

**悬空台子怎么看得见**：`jumpHigh`（1.6 m）和 `bridgePier`（2.4 m）的**底面朝下**，正好被熔岩底光照亮——这是 M1-03 里"向下的面亮"的正面应用。所以高台**不需要任何额外补光**就能被看见。低台（0.8 m）的底面离地近，反而要加一圈底部反光边。

## 【3. 材质规格（全部复用现有材质）】

**不新增材质**。`Spire.ts` 已有三套：

| 材质 | 参数 | 用于 |
|---|---|---|
| `rockMaterial` | `color #2b2523`, `roughness 0.9`, `metalness 0.02`, `flatShading`, `map+bumpMap` 程序化岩石噪声, `bumpScale 0.18` | 壁垒、矮墙、护壁、镇石台体、全部平台 |
| `obsidianMaterial` | `color #141010`, `roughness 0.22`, `metalness 0.5`, `flatShading` | 棱柱、镇石铁针、各道具底部反光边 |
| `runeMaterial` | `color #0a0706`, `roughness 0.78`, `metalness 0.15`, `emissive #c4400e`, `emissiveIntensity 1.6` | 壁垒符文（橙） |

**护壁的冷青符文需要一个新的 rune 变体**——这是唯一需要新增的材质：

```ts
// 护壁符文：冷青，压暗到 0.9（对比灯塔的 2.2+）
const wardRuneMaterial = new THREE.MeshStandardNodeMaterial({
  color: new THREE.Color(0x0a0706),
  roughness: 0.78,
  metalness: 0.15,
  emissive: new THREE.Color(PALETTE.beacon),   // #9fe9ff，复用现有调色板
  emissiveIntensity: 0.9,
  flatShading: true,
});
```

**新增材质数：1**。draw call 从 3 批变 4 批，仍在预算内（<400）。

**不许做的事**：
- ❌ 不许给石头加自发光来"照亮"（M1-03 的教训）
- ❌ 不许给平台加符文（会让玩家误以为有魔法效果）
- ❌ 不许改 `rockMaterial` 的 `bumpScale`（会影响整座塔的观感）

## 【4. 破坏与特效规格】

### 4.1 破坏分级

| 道具 | 可破坏 | 破坏方式 | 碎片 | 时长 |
|---|---|---|---|---|
| 熔渣壁垒 | ✅ 240 HP | 冲撞撞碎 / 火雨砸碎 | 10 块 | 0.9 s |
| 塌陷矮墙 | ✅ 120 HP | 冲撞 / 火雨 | 6 块 | 0.6 s |
| 塔心护壁 | ✅ 600 HP | 冲撞 / 火雨（逐段） | 8 段 × 2 块 = 16 块 | 1.4 s |
| 寒铁镇石 | ✅ 200 HP | 自燃爆发 / 冲撞 | 5 块 + 光环消散 | 0.8 s |
| 黑曜石棱柱 | ❌ 永不破坏 | — | — | — |
| 跳跃平台 | ❌ 永不破坏 | — | — | — |
**棱柱和平台为什么永不破坏**：棱柱是阶段 II 制造膝弱点的**唯一工具**，能被打掉就等于随机剥夺玩家解法。平台是地形，破坏了会让玩家突然掉进熔岩，属于"不可接受的随机死亡"。

### 4.2 碎片实现（InstancedMesh）

```
预制一个碎片池：InstancedMesh(BoxGeometry(1,1,1), rockMaterial, 64)
每块碎片：
  - 初始位置 = 原几何上的采样点
  - 初始速度 = 从爆炸中心向外的随机方向 × (3~7 m/s) + 向上 2~4 m/s
  - 角速度 = 随机 ±4 rad/s
  - 重力 = -14 m/s²（与玩家同一常量）
  - 落地判定：y < -1.8（arena.lava.startY）→ 沉入熔岩，播 0.3 s 缩小到 0
  - 生命周期 = 2.2 s（与 boss.json 的 transition.shardLifetimeMs 一致）
```

**复用 `boss.json` 的 `transition` 参数**（`shardCount 48`、`shardSpeedMps 9`、`shardLifetimeMs 2200`）：阶段转换的岩甲崩裂已经有成熟的碎片参数，道具破碎直接沿用同一套手感，**玩家感知一致**，也省一套调参。

**碎片上限 64**：29 件道具理论上同时最多碎 4~5 件（火雨一次砸 10 个点，但半径 3.5 m 不会同时覆盖 5 件），64 是安全余量。

### 4.3 破坏前兆（重要：给玩家反应时间）

**道具不会"突然"消失**。HP 降到 50% 时开始给信号：

| HP 区间 | 视觉信号 | 目的 |
|---|---|---|
| 100% → 50% | 无 | — |
| 50% → 25% | 裂缝处透出橙色微光（`emissiveIntensity` 0 → 0.4） | 告诉玩家"这东西在挨打" |
| 25% → 0% | 微光加强到 0.8，并开始 0.15 s 一次的闪烁 | 告诉玩家"快碎了，换掩体" |

**实现方式**：不用改材质，用**在裂缝位置叠加一层薄的发光条**（`BoxGeometry` + rune 材质），按 HP 比例调 `opacity`。这样不需要为每件道具克隆材质。

### 4.4 三种特效（都要做，但可以分批）

| 特效 | 触发 | 规格 | 预算 |
|---|---|---|---|
| **冲撞撞柱火花** | `lavaCharge` 撞到棱柱/壁垒 | 12 个火星粒子，从撞击点向四周抛，寿命 0.6 s，颜色 `#ffb060` | 复用 `Atmosphere` 的 ember 粒子池 |
| **护壁破碎尘** | 护壁某段 HP 归零 | 8 个灰色粒子缓慢上升，寿命 1.2 s | 同上 |
| **镇石光环脉冲** | 玩家进入/离开光环 | 光环 `opacity` 从 0.15 → 0.45 → 0.15，0.4 s | 单个材质动画，零成本 |

**不做**：屏幕震动（撞柱已经有 Boss 的眩晕震屏，叠加会过载）、镜头特效（会干扰玩家读 Boss 前摇）。

## 【5. 音频规格（全部复用现有素材）】

`molten-heart-audio` 包里有 40 个成品音效。**本票不需要新增任何音频资产**，只做映射：

| 触发事件 | 复用素材 | 参数 | 依据 |
|---|---|---|---|
| 冲撞撞到棱柱 | `sfx-boss-slam` | 音量 0.9，音高 ×0.85（更闷） | 已是"巨掌砸落"，与撞柱的物理感一致 |
| 壁垒/矮墙被撞碎 | `sfx-tower-destroy` | 音量 0.8，音高 ×1.05 | 已是"石塔崩解"，语义完全匹配 |
| 护壁逐段碎裂 | `sfx-tower-destroy` | 音量 0.55，音高 ×1.2，每段限频 120 ms | 避免 8 段同时响成噪音 |
| 镇石被摧毁 | `sfx-freeze` | 音量 0.7，音高 ×0.9 | 寒晶冻结音，与"寒铁"语义一致 |
| 镇石光环生效 | `sfx-tower-frost` | 音量 0.35，限频 400 ms | 寒晶蓄能音，短促不打扰 |
| 玩家踏上平台 | 无 | — | **刻意不加音效**：平台是地形，加音效会让玩家以为触发了什么 |
| 火雨砸中护壁 | `sfx-boss-fire` | 音量 0.6 | 已是"熔火轰击" |

**三条硬规则**：

1. **同一帧最多 2 个道具音**（与 `INTEGRATION.md` 里"同帧多塔被毁限制为 2 个声部"一致）。
2. **撞柱音必须压过破碎音**：撞柱是"玩家主动创造的事件"，破碎是"被动结果"。前者音量 0.9，后者 0.8。
3. **平台无音**（见上表）。

## 【6. 可读性与玩家引导】

### 6.1 玩家怎么知道"这个能挡吐息"

**不做 UI 标记**。靠三件事自然传达：

1. **前摇期的高亮**：Boss 放 `magmaBreath` 的 1.4 s 前摇里，所有 `blocksLos && losTopY ≥ 1.2` 的道具**边缘亮起**（obsidian 材质 `metalness` 从 0.5 提到 0.8，视觉上更反光）。这不是 UI，是材质响应。
2. **首次被挡的提示**：玩家第一次成功用掩体挡下吐息时，弹一行 3 s 的文字「掩体挡住了它」（复用 M4-01 的 `Narration` 事件，`speaker: 'narrator'`）。**只弹一次**。
3. **被击中的方向感**：吐息穿过来打中玩家时，屏幕边缘从受击方向泛橙（M4-01 的 HUD 已有"弱点方向脉冲"，复用同一套）。

### 6.2 玩家怎么知道"这个平台能站上去"

**平台顶部加一圈极细的发光描边**（`RingGeometry(0.85, 0.95, 8)`，rune 材质，`emissiveIntensity 0.5`）。

**为什么平台不给符文但给描边**：符文是"面"，描边是"边"。面会让人以为有魔法效果，边只是"勾出轮廓"。而且描边在纯黑环境里能**让平台的边界可读**——否则玩家跳上去会踩空。

这条**推翻了 §2.6 的"平台不用符文"**吗？不。§2.6 说的是不用符文（面），这里说的是描边（边）。两者不冲突，但要在实现时明确：**平台只有边，没有面。**

### 6.3 色盲/对比度自检

道具的三类颜色（橙 / 冷青 / 无符文）在**红色盲**视角下：

- 橙 `#ff8a3c` 与冷青 `#9fe9ff` 的**明度差足够**（橙较暗、青较亮），红绿色盲仍能分辨。
- 但**橙符文与熔岩同色系**，可能混在背景里。**对策**：符文用 `#ff9a3c`（比熔岩 `#ff5a12` 更黄），且在符文外圈加一道 1px 的暗边。

**这条需要实测**：建议用浏览器的色盲模拟模式截图对比一次。**标注为待实测。**

**draw call 增量**：

| 批次 | 增量 |

## 【8. 边界情况（这些不写清楚，实现时必踩）】

| 情况 | 规格 |
|---|---|
| **道具与塔重叠** | 父票已保证 2.2 m 净空。但塔是后建的，若玩家在道具旁建塔 → 塔位是固定的 11 个，道具不占塔位，**不会重叠** |
| **道具被熔岩淹没** | 狂暴期熔岩涨到 -0.6。所有道具底在 y=0，**不会被淹**。但 `bridgePier`（2.4 m）会成为最后的高地 |
| **Boss 站在道具里** | Boss 半径 2.6 m，道具最宽 5.0 m。Boss 的移动**不做道具碰撞**（只做撞柱检测），所以会穿过去。**这是可接受的**：Boss 是巨兽，撞碎掩体是设计意图 |
| **玩家站在平台上被跃击** | 跃击按 2D 位置判定，玩家在 1.6 m 高台上**仍会被砸到**。这是父票 §2 的明确设计（"跳起来还在圈里"） |
| **玩家卡在平台侧面** | `PlayerController` 的单轴推出（`moveAxis`）会把玩家推出去，不会卡住。但**快速斜向撞角落**可能抖动，属已知的 AABB 局限，本票不修 |
| **道具碎片挡住视线** | 碎片只是视觉，**不参与 LOS 判定**。否则一次破碎会临时创造掩体，产生不可预期的判定 |
| **护壁碎一半** | 逐段破坏。**LOS 按剩余段数判定**：某段 HP 归零则该段不再阻挡。这需要 LOS 实现支持"分段"（父票 §3 的规则要扩展为"逐段射线测试"） |

**最后一条是父票的遗漏**：父票把护壁当成一个整体矩形，但实际是 8 段。实现时必须按段判定，否则"打碎护壁中间一段，吐息仍被整面挡住"会很怪。**标注为实现时的必须修正项。**
