## 【为什么需要这张票】

三件事凑在一起，让现在的 Boss 战**没有走位可言**：

1. **场上是纯平地。** `GameLoop.buildPlayerWorld()` 只给了一个 AABB：
   `{ minX:-34, maxX:34, minY:-2, maxY:0, minZ:-34, maxZ:34 }`。整个可玩空间是一块 68×68 的板，**没有任何高度差、没有任何可躲避的实体**。
2. **Boss 的三个技能都是"罚站"型。** 熔岩吐息（20 m 锥形、每 0.25 s 判 8 伤）、岩拳横扫（120° 扇形）、熔岩冲撞（22 m/s 直线）——这三招的正确应对**全部是"走开"**，而走开这件事在平地上没有技巧含量。
3. **M3-01 验收第 7 条现在是空的。** 原文：「熔岩冲撞撞到塔/石柱/场地边界 → 眩晕 3 s 且双膝同时暴露」。场上**没有石柱**，这条验收只可能靠"撞场地边界"通过，而边界半径 19 m 之外 Boss 追不到，玩家会直接跑到外圈摆烂。

所以这张票要补的不是装饰，是**把"走位"变成一种有成本、有收益、有取舍的决策**。

## 【设计原则（先立规矩，再摆东西）】

| # | 原则 | 具体约束 |
|---|---|---|
| 1 | **道具不能替代操作** | 任何道具都不能让玩家"站着不动也不掉血"。所有掩体都有方向性，绕过去就失效。 |
| 2 | **道具不占熔核** | 全部预置。熔核经济已经很紧（开局 6，Boss 每掉 10% 才 +1，塔造价 2–3），再分给道具会挤掉塔，直接违背"塔 30% / 普攻 35% / 击破 35%"的伤害结构。 |
| 3 | **道具不挡塔的弹道** | 逻辑层塔没有 LOS 概念（`TowerSystem` 只判距离），所以道具**必须**全部落在塔心 7 m 之外，避免出现"塔在掩体后面打不到 Boss"的错觉。 |
| 4 | **不扩大无敌外圈** | 所有道具外缘 r ≤ 19（Boss 活动边界）。逻辑地面宽到 r=34 是现存绕过点，本票不去扩大它。 |
| 5 | **地形只加高度，不加新机制** | 跳跃平台只往 `world.colliders` 里塞 AABB —— 这是**零代码改动**就能生效的道具类型。遮挡物/防御物才需要新逻辑（见 §8）。 |
| 6 | **视觉服从 M1-03 的结论** | 不用自发光救石头。道具靠光照显现，材质与 `Spire` 的岩石/黑曜石一致，静态几何合并进现有三批。 |

### 1.3 跳跃平台（platform）· 12 件（4 条链 × 3 级）

| 链 | 角度 | 低台 (h=0.8) | 高台 (h=1.6) | 残墩 (h=2.4) |
|---|---|---|---|---|
| 1 | 22.5° | L1 (12.20, 5.05) | L2 (14.23, 5.89) | L3 (16.26, 6.74) |

| 3 | 202.5° | L7 (-12.20, -5.05) | L8 (-14.23, -5.89) | L9 (-16.26, -6.74) |
| 4 | 337.5° | L10 (12.20, -5.05) | L11 (14.23, -5.89) | L12 (16.26, -6.74) |

**为什么是三级而不是一块台阶**（这是本票最核心的数值推导）：

玩家跳跃能力（由 `player.json` 真实值反解，校验脚本会重算）：

```
重力 g = 14.0 m/s²        跳跃高度 h = 1.2 m
初速 v₀ = √(2gh) = 5.7966 m/s
滞空 T = 2v₀/g = 0.8281 s
走跳水平距离 = 6.5 × 0.8281 = 5.383 m
冲刺跳水平距离 = 6.5 × (0.8281 − 0.25) + 11.0 × 0.25 = 6.508 m
```

由此得出**设计安全上限**（留余量，不是极限值）：

| 参数 | 极限值 | 设计上限 | 本票取值 |
|---|---|---|---|
| 单跳可抬升 | 1.2 m | **0.9 m** | 每级 0.8 m ✅ |
| 走跳可跨间隙 | 5.38 m | **3.0 m** | 平台间隙 0.4 m ✅ |
| 冲刺跳可跨间隙 | 6.51 m | **5.0 m** | — |

于是：**0.8 → 1.6 → 2.4，每级 +0.8 m，都在 0.9 m 安全线内；但 1.6 m 和 2.4 m 都超过 1.2 m 单跳极限，所以从地面直上高台/残墩在物理上做不到。** 玩家必须走"低台 → 高台 → 残墩"。

这不是为了刁难，是为了让平台**有路线**：一块 1.2 m 的台子只是台阶，三级链才是"要不要花 3 秒爬上去"的决策。

**注意 `handleDash()` 不检查 `grounded`**（`PlayerController.ts:231-248` 只查 `dashTimer`/`dashCooldown`），所以空中冲刺合法。这意味着冲刺跳的 6.51 m 是真的可达值，但本票**不把任何间隙设计到需要冲刺跳**——冲刺留给躲技能，不该被地形绑死。

## 【§3 视线（LOS）判定规则】

逻辑层目前**没有 LOS 概念**。要落地遮挡物，必须新增一条纯函数判定：

```
2D 射线：从 Boss 胸口 (bx, bz) 到玩家胸口 (px, pz)
判定高度：losRayHeightY = 1.2 m（玩家蹲不下，取胸口）
道具挡得住 ⟺ blocksLos = true
             ∧ losBottomY ≤ 1.2 ≤ losTopY
             ∧ 线段与道具 2D 外包圆相交
```

**为什么用 2D 而不是 3D**：Boss 高 9–11 m、玩家 1.8 m，两者胸口高度差太大，3D 射线会让所有道具都挡不住。取"玩家胸口高度"这一个平面做 2D 判定，语义最稳定，也最好测。

**护壁必须逐段判定（子票 M3-04b 修正）**：护壁不是一块整体矩形，而是 **8 段**拼成的弧形。某段 HP 归零后，该段不再阻挡视线。若按整体矩形判定，会出现"打碎护壁中间一段，吐息仍被整面挡住"的怪现象。实现时 LOS 要对每段分别做射线测试，任一存活段相交即算挡住。

校验脚本用这条规则做了两个方向的断言：

- `breath-canonical`（Boss 出生位 → 玩家出生点）：**必须**被 B1/B2 挡住 → 证明"开局位置就能躲吐息"成立
- `breath-flank-unguarded`（侧翼 9.5, 17.0）：**必须**挡不住 → 证明掩体有方向性，不是全场无敌罩

## 【§4 与现有几何的冲突处理】

场地不是空地，`Spire.ts` 里已经有大量几何。本票所有坐标都避开了它们，规则如下（校验脚本逐件断言）：

| 避让对象 | 数值依据 | 处理 |
|---|---|---|
| 塔身主体 | `visual.json` `spire.tower.circumradius = 7` | 所有道具 r > 7，且最近道具距塔身 > 2.5 m |
| 中环塔位底座 | `midRing.slotAngles = [45,135,225,315]`，`slotRadius = 16.75`，`slotRadiusSize = 1.9` | 道具与 11 个逻辑塔位净空 ≥ 2.2 m（逐件断言） |
| 4 条石桥 | `bridges.angles = [0,90,180,270]`，`inner 20 → outer 32`，`width 2.4` | 道具不落在桥面投影内（逐件断言） |
| 玩家出生点 | `arena.json` 实际 `spawn = [0, 0, 22]`（`GameLoop` 里也是 z=22） | 净空 ≥ 1.5 m |
| Boss 出生点 | `main.ts` 里 `boss.root.position.set(0, 0, 11)` | 净空 ≥ 3.2 m |

**发现的一处不一致（只报告，不修改）**：`boss.json` 的 `arena.spawn = [0, 0, 12]`，但 `main.ts` 实际写的是 `(0, 0, 11)`，`GameLoop` 的玩家 spawn 是 `(0, 0, 22)`。三个数各说各的。本设计以**代码实际值**为准（Boss z=11、玩家 z=22），并建议 S0 把 `boss.json` 的 `arena.spawn` 改成 11 或让代码读 config。这属于 S0 的 config 职责，本票不动。

## 【§6 落地路径（三种，按成本排序）】

### 路径 A · 只做跳跃平台（**零代码改动**，1 小时）

跳跃平台只需要往 `GameLoop.buildPlayerWorld()` 的 `colliders` 数组里加 AABB：

```ts
// 由 config 驱动，不是硬编码
colliders: [
  { minX: -34, maxX: 34, minY: -2, maxY: 0, minZ: -34, maxZ: 34 },
  ...propsCfg.instances
    .filter(p => p.kind.startsWith('jump'))
    .map(p => aabbFromFootprint(p)),   // 中心 (x,z) ± 0.9，minY 0，maxY = height
]
```

`PlayerController.integrateVertical()` 已经有完整的"落地/撞头/吸附"逻辑（`PlayerController.ts:290-339`），**加 AABB 就能用**。这是性价比最高的一步，建议先做。

### 路径 B · 加遮挡物（需要新逻辑，约半天）

需要三件东西：

1. **`src/core/config/arena-props.json`**（S0 落库，结构见 config 草案）
2. **`src/boss/LineOfSight.ts`**（纯逻辑，禁 three）：`isBlocked(from, to, props): boolean`
3. **Boss 侧接入**：`magmaBreath` 的 tick 判定里加 LOS 检查；`lavaCharge` 的移动里加"撞到柱/墙"的检测

### 路径 C · 加防御物（最贵，约 1 天）

需要 `TowerSystem` 与护壁的伤害转移、火雨落点与护壁的相交判定、镇石光环的玩家减伤。**建议排在 M4 之后**，或者在时间不够时只做 W1（单个护壁）验证机制。

## 【§7 验收（每条都能重跑）】

### 7.1 自动校验（已有，可立即跑）

```bash
node docs/tickets/M3-04-validate.mjs
```

当前输出：**189 项断言，0 失败**。覆盖：

1. 可达性数学与 `player.json` 重算一致（跳跃高度/滞空/水平距离）
2. 4 条平台链每一跳的抬升与间隙都在安全上限内
3. 高台/残墩从地面直上**必须做不到**（否则两段跳设计失效）
4. 29 件道具与 11 个塔位净空 ≥ 2.2 m
5. 不压 4 条石桥
6. 玩家/Boss 出生点净空
7. 所有道具外缘 r ≤ 19（不造无敌外圈）
8. 吐息 canonical 射线**必须**被 B1/B2 挡住；侧翼射线**必须**挡不住

### 8.2 新增事件（最小集，2 个）

```ts
// Events 里追加
/** 道具耐久变化。place 时不需要，因为道具全是预置的，初值从 config 读。 */
PropHpChanged: { propId: string; hp: number; maxHp: number };

PropDestroyed: { propId: string; kind: string; reason: 'charge' | 'fireRain' | 'ignite' };
```

**能复用现有事件的部分（不新增）**：

- 撞柱眩晕 → 复用 `BossSkillInterrupted{by:'stagger'}` + `KneeBroken{side}`，**不需要新事件**
- 玩家站上平台 → 不需要事件，`PlayerController` 内部 `grounded` 变化即可
- 镇石减伤 → 复用 `PlayerDamaged`，只是 `amount` 已经减过

### 8.3 Snapshot 新增 1 个字段

```ts
export interface Snapshot {
  // ...原有字段不动...
  /** 当前存活的场地道具。UI/渲染用来画护壁耐久条、镇石光环。 */
  props: Array<{ id: string; kind: string; hp: number; maxHp: number }>;
```

**注意**：`props` 数组每帧都读会分配内存。建议只在 `PropHpChanged` / `PropDestroyed` 时重建，与现有 `towers` 的做法一致。

## 【§9 明确不做】

| 不做 | 原因 |
|---|---|
| 可建造道具（花熔核买） | 熔核经济太紧，会挤掉塔。预置才能保证平衡可测 |
| 道具升级 / 维修 | 增加 UI 与操作负担，与"4:30 节奏"冲突 |
| 单向平台（可从下方穿过） | 当前 AABB 逻辑不支持，要改 `PlayerController` 的垂直判定，成本高于收益 |
| 可移动 / 可推动的道具 | 同上，且会让 Boss AI 的距离判定复杂化 |
| 破坏后重建 | 本票的道具是一次性的，碎了就没了。重建会让"牺牲护壁"这个决策消失 |
| 扩大可玩地面半径 | 逻辑地面已经宽到 r=34，比 Boss 边界 19 大。这是现存绕过点，本票不扩大，但也不修（属 S0/整合层职责） |
