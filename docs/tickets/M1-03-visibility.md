# 票 M1-03 · 石头必须看得见（M1-02 调过头了）

> 这张票是**我上一张票的设计缺陷**造成的，不是执行问题。M1-02 里我要求"关掉所有灯岩体应该什么都不亮"，做完之后石头确实不亮了——但也**彻底看不见了**。

## 【问题：一张图说明】

三张验收截图：

| 图 | 机位 | 结果 |
|---|---|---|
| shot3 | 底层仰望 | **成功**。拱廊、立柱、天花板纹理、熔心核护罩都清晰可读 |
| shot1 | 塔顶平视 | **失败**。全黑，只剩橙色和青色的发光线，像霓虹线框图 |
| shot2 | 塔顶俯视 | **半失败**。中央熔岩海很好，但周围平台与矮墙全是黑的 |

暗部占比（luma < 0.05）也证实了：shot1 86.6%、shot2 87.4%，而 shot3 只有 32.0%。

**根因**：光从下往上打，所以向下的面被照亮、向上的面照度为 0。玩家站在塔顶平视/俯视时，看到的地面、墙顶、平台面**全部是"向上的面"**——也就是全部是黑的。第一人称玩家 90% 的时间都在平视和俯视，等于 90% 的时间看不到石头。

石头的可读性现在完全依赖发光线，这就是"霓虹灯"感的来源。

## 【修法：给向上的表面一点照度，但不破坏"暗部要黑"】

物理上讲得通：地心穹顶本身是被熔岩照亮过的岩石，它会向下方**散射反射**一部分光。所以向上的表面不是零照度，而是"很弱、偏冷、无方向性"的补光。

### 改动 1：半球光提亮并偏冷（`Atmosphere.ts`）

```ts
// 之前：new THREE.HemisphereLight(0x1a0d08, 0xff4a0a, 0.5)
// 之后：
new THREE.HemisphereLight(0x4a3326, 0xff4a0a, 0.85)
```

sky 色从近黑 `#1a0d08` 提到 `#4a3326`（暗棕灰，模拟穹顶反射），强度 0.5 → 0.85。
ground 保持 `#ff4a0a`，**ground 必须仍然明显亮于 sky**，否则上下方向感就没了。

### 改动 2：加一盏从正上方下来的极弱冷光

```ts
const skyFill = new THREE.DirectionalLight(0x8a6a58, 0.45);
skyFill.position.set(0, 80, 0);
skyFill.target.position.set(0, 0, 0);
// 不投影（省预算，且这盏灯只负责"让石头能被看见"）
```

这盏灯的作用只有一个：让向上的表面有 **6%–12%** 的亮度，足以读出石头的形状和纹理，但远低于向下表面的亮度，不破坏"光从下面来"的主次关系。

### 改动 3：石头材质回一点点自发光？——不，不要

**不要**用自发光救石头。上一轮的教训：自发光 + Bloom 会把画面变成霓虹灯。
石头只能靠**光照**显现，这是纹理和法线的工作。

### 改动 4：确认岩石 map 贴图可见

现在石头纯黑，512² 噪声贴图等于白做。改完光照后，检查：
- 塔顶平台面（平视）能看出 34 块大斑驳
- 矮墙侧面能看出凹凸
- 若看不清，把 `bumpScale` 从 0.18 提到 0.3

## 【验收（这次的重点不是数字，是"看不看得见"）】

### 硬指标

1. **暗部占比必须是这个样子**：shot1 从 86.6% 降到 **50%–65%**；shot2 从 87.4% 降到 **55%–70%**；shot3 从 32.0% 升到 **35%–45%**（可以因加了补光而略升）。
   —— 不是越黑越好，也不是越亮越好，要的是"中间调回来"。
2. 四条命令全绿（typecheck / build / pack / check）。
3. Draw call 仍 < 400，三角 < 1.2M。

### 人眼指标（这条比数字重要）

重新出三张 1080p 截图，**在关掉所有后处理（`?off=all`）的情况下再各出一张**。要求：

- **关掉后处理之后，仍然能一眼看出"这是一座石塔"**：能分辨平台是平的、矮墙是立着的、塔身是八棱的。
- 如果关掉后处理就只剩黑底和线，说明照度还是不够，继续加。
- 反过来，如果关掉后处理之后整张图**亮度均匀、看不出光从下面来**，说明补光加过头了，往回收。

判据一句话：**「能看出石头，但仍觉得下面很亮、上面很暗」**。

## 【顺带解决帧时间（这是第二个问题）】

TRAE 报告：720p / high 档 96.1 ms，low 61.8 ms，纯场景 36.9 ms。并说明机器是 Intel Gen-12LP 核显、测量期间另有 headless Chrome 占 44% GPU。

两件事要做：

### 1. 默认画质档降一档

现场演示的机器大概率也是核显。把首 3 秒自动选档的阈值往上提，让它在核显上自动落到 `medium` 而不是 `high`：

```
平均帧时间 > 30ms  → low
平均帧时间 > 18ms  → medium   （原来 > 17ms 是 medium，这里把 high 的门槛抬高）
其余              → high
```

**`ultra` 永远不自动选，只能人工 `?quality=ultra`。**

### 2. 高开销项在 medium 档默认关闭

| 项 | high | medium（新默认） |
|---|---|---|
| GTAO | 0.5×/12 samples | **关** |
| SSR | 0.35 | **关** |
| 体积光 | 24 tap | 12 tap |
| Bloom | 0.5× | 0.5× |
| 运动模糊 | 8 | 关 |
| TRAA | 开 | 开 |
| LUT + 色差 + 暗角 + 颗粒 | 开 | 开 |

理由：GTAO 和 SSR 在"光从下往上、场景大面积纯黑"的画面里收益极低，但开销很大。关掉它们，帧时间能砍掉一半，而观感几乎不变。

### 3. 交付时贴一组干净的数据

请在没有其他进程抢 GPU 的时候，单独测一次 1080p 各档帧时间，注明档位与机器。**测不了就明说测不了**，不要拿被抢占时的数字当结论。

## 【不许做的事】

- 不许用自发光把石头"照亮"（这是上一轮的错）
- 不许把 ground 光调暗来平衡（ground 必须仍是全场最亮的光源）
- 不许为了让截图好看而临时调参数——验收看的是默认配置
