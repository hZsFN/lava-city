# 票 M5-01 · HUD 与结算页

> 目标：让玩家在任何时刻都知道"我是谁、我还剩多少、Boss 打到哪了、我能干什么"。
> 这一票不加任何玩法，只做"看得见"。
> **只允许改 `src/ui/`、`index.html` 的样式块。不许碰 `src/render/`、`src/game/`、`src/boss/`。**

## 【总原则】

- 原生 DOM + CSS，**不引任何 UI 框架**，不装依赖。
- 只订阅事件总线 + 读 `bus.snapshot()`，**不持有任何逻辑对象**，不调用 `three`。
- 所有颜色 / 字号 / 动效时长从 `src/core/config/ui.json` 读，不写死在 CSS 里。
- 属性色必须引用 `visual.json`：法术 `#4aa8ff`、物理 `#f0e6cf`（白金）。
- DOM 更新节流到**每帧最多一次**（在 `app.onSync` 里统一 flush，不要在事件回调里直接改 DOM）。

## 【必须做的六块】

### 1. 左下角 · 玩家状态

```
┌─ HP 条（横向，宽 260px 高 10px）
│    当前 hp / maxHp 实时画。**开局可能只有 1 点血，这是正常的，不要显示成"异常"**
│    颜色：hp ≤ 1 时整条脉动（0.8s 周期，opacity 0.55↔1）
├─ 形态图标（圆形 44px）+ 名字（物理 / 法术）
│    切换时 0.25s 缩放弹一下；边框色 = 当前形态属性色
└─ 过热条（仅法术形态显示，宽 180px 高 6px）
     满条变红并闪烁，冷却时从上往下退
```

数据来源：`snapshot().player.{hp,maxHp,form,overheat}`。

### 2. 顶部中央 · 倒计时

大号数字 `M:SS`，从 `flow.json` 的 `matchLengthSec`（270）倒计到 0。
- 剩余 < 60 s 变橙、< 30 s 变红并每秒脉动一次。
- 下方一行小字显示当前阶段中文名：醒来 / 阅读 / 准备 / 岩甲形态 / 转变 / 熔火形态 / 熔岩吞没。
- 数据来源：`snapshot().phase` + `phaseRemainSec`。

### 3. 顶部 · Boss 双段血条

**两段条叠在一起**，上段是当前阶段，下段是下一阶段（灰掉）。
- 当前阶段条：高 14px，宽 620px，居中，左右各带一个属性抗性图标（物理盾 / 法术盾），抗性 ≥ 50% 时图标发亮。
- 血条左端显示 `IGNIS · 伊格纳斯`，右端显示 `阶段 I` / `阶段 II`。
- 血条下方挂 debuff 层数：`碎甲 ×N` / `灼烙 ×N` / `冻结 N%`，各带属性色圆点。
- 阶段切换时整条重绘，并闪一次白金横光。
- 数据来源：`BossSpawned` / `BossHpChanged` / `BossPhaseChanged` / `DebuffStackChanged` / `FreezeProgressChanged`。

### 4. 屏幕中央 · 准星与破绽环

- 准星：一个小十字（4 条 8px 线，间隔 6px），默认 `rgba(255,255,255,0.55)`。
- 命中 Boss 弱点且属性匹配时：准星变成对应属性色，并向外扩一圈。
- **破绽环**：准星外一圈 64px 的圆环，按 `WeaknessProgress` 的 `value/max` 填充；满时整环变白金并脉动，同时浮现 `[F] 击破` 提示。
- 数据来源：`WeaknessExposed` / `WeaknessClosed` / `WeaknessProgress`。

### 5. 屏幕边缘 · 弱点方向指示

弱点暴露时，在**屏幕边缘**画一个箭头指向该弱点的屏幕投影方向（拿不到投影就按世界坐标与玩家朝向算方位角）。
- 箭头颜色 = 弱点属性色，未被属性匹配时半透明（opacity 0.45）。
- 三秒内没有朝向它的话，箭头脉冲一次提醒。
- 数据来源：`WeaknessExposed{part, attr}` + 玩家朝向 + Boss 位置。

### 6. 右下角 · 资源与结算

- **熔核**：一个火苗图标 + 数字，变化时数字弹一下。
- **战术点**：一个菱形图标 + 数字（没有就隐藏）。
- 数据来源：`MoteCountChanged` + `TacticalViewChanged`。

### 7. 结算页（局终覆盖层）

`MatchEnded` 时全屏淡入（0.4 s），内容：
```
大字：守护成功 / 塔心熄灭
副标题：用时 3:42 · 击破 3 次
评分：S / A / B / C（用时 < 3:30 且零死亡 = S；< 4:00 = A；通关 = B；失败 = C）
伤害构成条形图：塔 / 普攻 / 击破 三段，比例用真实累计值
底部：[再来一局]（≤ 2 s 重开）
```
**失败时不许白屏**，必须显示"塔心熄灭了"+ 失败原因中文（`hp_zero` → "你的血耗尽了"、`core_zero` → "塔心被摧毁"、`timeout` → "熔岩吞没了塔顶"）。

## 【验收】

1. `npm run typecheck` + `npm run build` + `node kit/tools/check.mjs out/` 全过。
2. 起 `npm run dev`，用调试键制造以下状态并各截一张图（放 `docs/shots/hud/`）：
   - 开局 1 点血（把存档 hp 改成 1）
   - Boss 阶段 I、弱点暴露中、破绽环半满
   - 阶段切换瞬间
   - 结算页成功
   - 结算页失败
3. 1080p 下 HUD 总覆盖面积不超过屏幕 18%（用 DOM 元素面积估算），不得遮挡准星周围 120×120 的中心区。
4. 全屏截图里所有文字在 1080p 下可读（字号 ≥ 12px，对比度 ≥ 4.5:1）。

## 【不许做的事】

- 不许用 canvas 画 HUD（必须 DOM，便于随时改样式）。
- 不许在事件回调里直接写 DOM（一律进队列，`onSync` 统一 flush）。
- 不许显示"死亡次数"——血量接力规则下我们不管理复活，死亡即失败。
- 不许出现"你在打黑客松""AI 生成"这类出戏文案（验收会扫）。
