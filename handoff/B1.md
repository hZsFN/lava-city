### 给 B2 / B3 / S0 的接线说明

**B2**：`place()` 从 `kinds/index.ts` 的 `TOWER_BEHAVIORS` 取行为。B2 只要 import 并在表里加一行，B1 自动生效，**不用通知我**。
- `TowerRuntime.bus` 是**每塔一层守卫总线**：转发全部事件，但在仰角死区内会吞掉 `TowerTargetHit`。B2 正常 `self.bus.emit(...)` 即可，不需要自己判死区。
- `ctx.canFire` 在死区内也会被置 `false`，B2 可以据此提前收手（双保险，但**不是必须**）。
- `onPlaced` 在 `buildSec`（0.5 s）结束时调一次，`buildSec` 期间 `behavior.update` 不会被调用。
- `onRemoved` 在 `sell` / `broken` / `drowned` 三种销毁路径下都会调一次。
- `onDamaged(self, amount)` 若返回非有限值，B1 按 hp=0 处理（即视为打死）。

**B3**：`TowerSystem.init()` 内部已订阅 `MatchPhaseChanged` → `setPhase()`、`LavaLevelChanged` → `setLavaY()`。B3 **只发事件就行**，不要直接调 `setPhase`/`setLavaY`，否则会重复处理（虽然幂等，但会多跑一遍）。两者不互相 import。

**S0 集成期**：`main.ts` 里 `createTowerSystem()` → `init({bus, rng, towersCfg, arenaCfg})` → 每帧 `update(dt, ctx)`。`ctx` 直接按 `TowerUpdateCtx` 组装即可。

### 跨目录请求 #2（11:50 提出）— 建议 S0 考虑 `SlotConfig` 加可选 `drownAtY`
- **现状**：`arena.json` 的 `slots[]` 没有 per-slot 淹没阈值，只有全局 `lava.drownSlotY`。
- **我的处理**：按几何关系推导 `drownAtY = drownSlotY + max(0, slot.y - 最低塔位y)`。当前 config 下平地塔位（M/E，y=0）= `-0.6`，塔身塔位（T，y=12）= `11.4`。同时**已支持** `slots[].drownAtY` 显式覆盖（可选字段，读到就用）。

## 设计说明（给 review 的人）

1. **事件由 TowerSystem 统一发，TowerSocket/TowerBase 不发任何事件** —— 避免同一状态变化两处 emit 导致重复。
2. **仰角死区做在分发层的「守卫总线」里**，而不是让 B2 每种塔各写一遍。理由是死区是塔位几何属性，与塔种无关；同时 `ctx.canFire` 也置 false 让行为能提前收手。
3. **`place()` 先校验后占位**：所有失败路径都在 `socket.occupy()` 之前返回，保证「失败零事件」；`occupy` 万一失败会回滚 `seq`。
4. **`sell()` / `destroyTower()` 先摘状态再广播**：监听方回调里若再调 `sell()` 不会重入。
5. **`locked` 槽位不参与淹没**：契约注释写的是「open/occupied → submerged」。另外补了「熔岩已涨上来之后才解锁外环 → 直接 submerged」的边界处理，避免 UI 闪一下 open。
6. **每塔独立种子**：`init` 传入的系统 rng 每建一座塔抽一个种子给该塔的 `rng`，保证整局可复现且各塔随机流互不干扰。
