**关键行为已落实**
1. 阶段严格按 `flow.json` 推进；每次切换发一次 `MatchPhaseChanged{phase, tSec}`，不重复发。
2. `update(1/60)` × 60 → `tSec() ≈ 1.0`，误差 < 1e-6（有单测）。
3. 熔岩：`boss1` 段恒 `-1.8` → `transition` 线性升到 `-0.8`（15 s）→ `boss2` 保持 → `rage` 每秒 `+1.2`。
   变化量 < 0.01 且速率未变时不发 `LavaLevelChanged`（有单测：120 s 内事件数 < 10）。
4. `MatchEnded` 一局只发一次；之后 `notifyXxx` / `applyCoreDamage` 全部忽略（有单测）。
5. 5 种失败/胜利条件齐备：`boss_defeated` / `core_destroyed` / `player_out_of_lives` / `timeout` / `lava_swallowed`。
6. `applyCoreDamage` 扣血后广播 `CoreHpChanged`，归零即判负。

## 未完成 / 阻塞

无功能阻塞。以下 3 点是**设计口径需要 S0 裁决**，不影响本票交付：

1. **熔岩吞没线**：`arena.json` 没有「塔心高度」字段。当前按设计文档
   「4:30 整淹没塔心」推导吞没线 = `phase2RiseTo + rageRisePerSec × rage时长` = `-0.8 + 1.2×25 = 29.2`。
   即默认配置下熔岩在 270 s 恰好到吞没线，而硬上限优先，所以默认跑满一局是 `timeout` 而非 `lava_swallowed`。
   若希望熔岩更早吞没，需在 `arena.json` 加 `lava.swallowY`。
   **已实现为可配置**：传 `arenaCfg: { lava: { swallowY: N } }` 即生效（有单测验证该分支）。
2. **超时 vs 吞没同帧**：两者都在 270 s 时判 `timeout` 优先（硬上限优先，与设计文档「4:30 硬上限」一致）。
3. **提前结束补发 ended 阶段事件**：Boss 死/塔心爆时，先补发一次
   `MatchPhaseChanged{phase:'ended', tSec}` 再发 `MatchEnded`，避免 UI 停在旧阶段。
   若 S0 认为不该补发，改 `MatchTimeline.finish()` 一处即可。
